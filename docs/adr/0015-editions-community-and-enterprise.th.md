# ADR-0015: รุ่นของระบบ — Community ใช้ได้จริงฟรี และ Enterprise แบบเสียเงิน

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-25
- **แทนที่:** เฉพาะข้อ 4 ของ ADR-0012 ("ไม่มีรุ่นเสียเงิน")
- **English:** [0015-editions-community-and-enterprise.md](0015-editions-community-and-enterprise.md)

## บริบท

ADR-0012 สัญญาว่าทุกอย่างเปิดภายใต้ Apache 2.0 โดยไม่มีรุ่นเสียเงิน ตอนนี้เจ้าของโปรเจกต์ต้องการโมเดลธุรกิจแบบที่
เลี้ยง Odoo และผลิตภัณฑ์คล้ายกัน คือ:

- รุ่นฟรีที่ดีพอจะโหลดไปใช้งานจริง และเป็นผลงานโชว์สาธารณะไปในตัว
- รุ่นเสียเงินสำหรับความต้องการที่เชนขนาดใหญ่ยอมจ่าย

มีข้อเท็จจริงสามข้อที่บังคับการออกแบบ:

- โค้ดที่เผยแพร่ภายใต้ Apache 2.0 แล้ว ยังเป็น Apache 2.0 สำหรับทุกคนที่ได้รับไป สิ่งที่ฟรีวันนี้จะกลายเป็นของเสียเงิน
  ไม่ได้ ทั้งทางกฎหมายและในแง่ความน่าเชื่อถือ
- โปรเจกต์นี้สร้างโดยผู้ดูแลคนเดียวกับ dev session เดียว ถ้าแยกเป็นสองโค้ดเบสสอง CI ความเร็วจะหายไปครึ่งหนึ่ง
- เป้าหมายแรกของเจ้าของยังคือพิสูจน์ฝีมือในที่สาธารณะ โค้ดเสียเงินที่ไม่มีใครเห็นไม่ช่วยเป้าหมายนี้

## การตัดสินใจ

1. **PaynEat ERP มีสองรุ่น**

   | | Community | Enterprise |
   |---|---|---|
   | License | Apache 2.0 | เปิดให้อ่านโค้ดได้ ภายใต้ Elastic License 2.0 (ELv2) เปิดใช้ด้วย license key |
   | ราคา | ฟรี | ค่าสมาชิก |
   | โค้ดอยู่ที่ไหน | ใน repo ส่วนที่อยู่นอก `ee/` | `ee/` ใน repo public เดียวกัน |

2. **Community ใช้งานได้ครบสำหรับหนึ่งเชน ไม่ใช่ตัวทดลอง** มีทุกอย่างใน spec v1 (#1) และทุกการพัฒนาต่อในเส้นทาง
   ซัพพลายเออร์ถึงจานในภายหลัง:
   - บัญชีเคลื่อนไหวสต๊อก, lot และวันหมดอายุ, ต้นทุน
   - การตรวจรับ, การผลิต, การโอน, ใบขอเบิก, MRP-lite
   - การย้อนรอย recall, การตรวจนับ, การปิดงวด, การ export
   - การเชื่อม POS, ภาษาไทยและอังกฤษ
   - public API, token และ webhook ตาม ADR-0013

   ไม่จำกัดจำนวนผู้ใช้ สถานที่ รายการสินค้า หรือเอกสาร
3. **สิ่งที่จะไม่อยู่หลัง paywall** ไม่ว่ารุ่นไหน ตลอดไป:
   - ความปลอดภัยอาหารและความถูกต้องของข้อมูล: การบล็อกของหมดอายุ, การย้อนรอย recall, บัญชีสต๊อกแบบ
     append-only, การแยกหน้าที่, audit trail
   - ความปลอดภัยพื้นฐาน รวม MFA และการแก้ช่องโหว่
   - สิทธิ์ของเชนในการเข้าถึงข้อมูลตัวเอง รวม export ทั้งหมด
   - เส้นทางอัปเกรดที่มีเอกสารและผ่านการทดสอบ (ระดับ 2 ใน ADR-0012)

   **ฟีเจอร์ของ Community จะไม่ถูกย้ายไป Enterprise**
4. **Enterprise สำหรับความต้องการที่โตตามขนาด ตามกฎระเบียบ หรือมีต้นทุนในการรัน** รายการแรกที่จะยืนยันกับเชนนำร่อง
   ก่อนสร้าง:
   - **หลายบริษัทและหลายโรงงาน:** หลายนิติบุคคลในระบบเดียว, โอนและตั้งราคาระหว่างบริษัท, วางแผนข้ามโรงงาน
   - **โปรแกรมความปลอดภัยอาหาร:** เฝ้าจุดควบคุมวิกฤต (HACCP CCP), บันทึกอุณหภูมิจากเซนเซอร์, คะแนนคุณภาพ
     และใบรับรองของซัพพลายเออร์, ซ้อม recall แบบจับเวลาพร้อมรายงานสำหรับ audit
   - **ย้อนรอยระดับสาขาแบบแม่นยำ:** สแกนแพ็กด้วยบาร์โค้ด GS1 แทนการอนุมานด้วย FEFO ส่วน Community ยังมี
     recall แบบบอก lot ที่เป็นไปได้ตามจริงของ ADR-0006
   - **การเงินเชิงลึก:** three-way matching พร้อมปรับมูลค่า, ปันค่าใช้จ่ายนำเข้า (landed cost) ลง lot, ต้นทุนมาตรฐาน
     พร้อมวิเคราะห์ผลต่าง
   - **แอปมือถือ** สำหรับรับของ ตรวจนับ และส่งของ
   - **ตัวเชื่อมสำเร็จรูป** กับโปรแกรมบัญชีเฉพาะยี่ห้อ ส่วน Community ยังมี export แบบทั่วไป
   - **AI agent** ที่มีค่าใช้จ่ายในการรัน: พยากรณ์ความต้องการและจังหวะการสั่งซื้อ, ตัวสืบสวนส่วนต่าง (ADR-0011)
   - **ระบบตัวตนระดับองค์กร:** single sign-on (SAML, OIDC) และการจัดการบัญชีผู้ใช้อัตโนมัติ
   - **ต้นทุนแรงงาน** จาก Cwork เข้าต้นทุนการผลิต
5. **บริการเสียเงิน ใช้ได้กับทั้งสองรุ่น:**
   - hosting ("PaynEat Cloud")
   - อัปเกรดให้ และย้ายข้อมูลจากระบบอื่น
   - support ที่มีระดับบริการ (SLA)
   - ติดตั้งวางระบบและอบรม
6. **คิดราคาต่อสถานที่ที่ใช้งาน** (โรงงาน คลัง หรือสาขา) ต่อเดือน **ไม่คิดต่อผู้ใช้**
   ร้านอาหารมีพนักงานมากและเข้าออกบ่อย ถ้าคิดต่อผู้ใช้ เชนจะแชร์บัญชีกัน ซึ่งทำให้ audit trail และการแยกหน้าที่
   (ADR-0008) พัง ตัวเลขราคากำหนดร่วมกับเชนนำร่องรายแรก ไม่เดาเอง
7. **การจัดโค้ด:**
   - โค้ด Enterprise อยู่ใน `ee/` และพึ่ง core ได้ **core ห้าม import จาก `ee/`** มี architecture check บังคับ
   - `ee/` เป็นโค้ดของเราเอง ทดสอบใน CI เดียวกัน และ release พร้อมกันด้วยเวอร์ชันเดียวกัน ADR-0013 ห้ามโค้ดของ
     คนนอกรันภายใน ERP แต่ไม่ได้ใช้กับ `ee/`
   - กฎของบัญชีสต๊อก (ADR-0003, ADR-0010) ใช้กับ `ee/` เหมือน module อื่นทุกตัว
   - license key มีลายเซ็นและตรวจแบบออฟไลน์ ไม่ส่งข้อมูลกลับมาหาเรา: สาขาอาจออฟไลน์ และข้อมูลของเชนไม่ใช่สิ่งที่
     เราควรเฝ้าดู
   - key หมดอายุแล้ว หน้าจอ Enterprise จะเป็นแบบอ่านอย่างเดียว แต่ไม่บล็อกงานหลัก การ post หรือการเข้าถึงข้อมูล
     เราจะไม่เอาข้อมูลของเชนไปเป็นตัวประกัน
8. **จังหวะเวลา:**
   - v1 เป็น **Community ทั้งหมด** แผนสัปดาห์ 1–6 และ issue ตั้งแต่ #2 ไม่เปลี่ยน
   - ยังไม่เขียนโค้ด `ee/` จนกว่า v1 จะ release และมีเชนนำร่อง จากนั้น PO จะออก issue ของ Enterprise
9. **PaynEat POS เป็น Community ทั้งหมด** สิ่งที่เก็บเงินได้ของ POS มีแค่บริการ (POS `DECISIONS.md` #67)
   ฟีเจอร์ Enterprise ที่เกี่ยวกับหน้าร้านจะมาผ่าน ERP
10. **ก่อนขายครั้งแรก:** ให้ทนายตรวจประกาศ ELv2 และเงื่อนไขการค้า และจดเครื่องหมายการค้าชื่อ PaynEat เพราะเมื่อ
    โค้ดเปิด สิ่งที่ขายจริงคือแบรนด์และบริการ

## ผลที่ตามมา

- ผลงานยังเห็นได้ครบ ทุกบรรทัดของทั้งสองรุ่นอ่านได้ใน repo public เดียว
- ผู้ใช้ Community ได้ผลิตภัณฑ์ที่ใช้งานได้จริง และรายการ "ไม่มีวันอยู่หลัง paywall" ในข้อ 3 เป็นข้อความสาธารณะ
  ความเชื่อใจจึงไม่ต้องพึ่งคำสัญญาลับๆ
- ใครก็เอา Community ไปให้บริการ hosting แก่คนอื่นได้ เพราะ Apache 2.0 อนุญาต แต่ ELv2 ห้ามเอา `ee/` ไปให้บริการ
  hosting โดยไม่มี license ยอมรับข้อนี้
- ทุกฟีเจอร์ใหม่ต้องตัดสินว่าอยู่รุ่นไหน PO เป็นคนตัดสินตามกฎในข้อ 2–4 และบันทึกไว้ใน issue นั้น
- README เพิ่มหัวข้อ "รุ่นของระบบ" และ GLOSSARY เพิ่มศัพท์ที่เกี่ยวข้อง

## ทางเลือกที่พิจารณาแล้ว

- **ฟรีทั้งหมดต่อไป (ADR-0012 ตามเดิม)** ปฏิเสธโดยเจ้าของโปรเจกต์: ไม่มีทางหล่อเลี้ยงโปรเจกต์
- **แยก repo ปิดสำหรับโค้ดเสียเงิน** ปฏิเสธ: ซ่อนงานที่ดีที่สุดจากผลงาน และผู้ดูแลคนเดียวต้องทำ CI กับ release
  สองเท่า
- **คิดราคาต่อผู้ใช้แบบ Odoo** ปฏิเสธด้วยเหตุผลเรื่อง audit trail ในข้อ 6
- **เปลี่ยน license ของ core เป็น AGPL เพื่อกันคนอื่นเอาไป host** ปฏิเสธ: โค้ดที่เผยแพร่แล้วยังเป็น Apache 2.0,
  POS ก็เป็น Apache 2.0 และการเปลี่ยน license เสียความเชื่อใจมากกว่าที่ปกป้องได้
- **จำกัด Community ด้วยจำนวนผู้ใช้ สถานที่ หรือปริมาณข้อมูล** ปฏิเสธ: จะกลายเป็นตัวทดลองใช้ ไม่ใช่ผลิตภัณฑ์
  ซึ่งตรงกับสิ่งที่เจ้าของไม่อยากให้คนคิด
