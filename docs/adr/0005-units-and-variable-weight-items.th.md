# ADR-0005: หน่วยนับและรายการน้ำหนักแปรผัน

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-25
- **English:** [0005-units-and-variable-weight-items.md](0005-units-and-variable-weight-items.md)

## บริบท

ซัพพลายเออร์เรียกเก็บเงินค่าไก่ตามน้ำหนักจริง โรงงานวางแผนเป็นจำนวนตัว ("วันนี้แยกชิ้น 500 ตัว") และสาขานับชิ้นส่วนที่
แบ่งแล้วเป็นชิ้น เนื้อสัตว์และอาหารทะเลไม่มีน้ำหนักต่อชิ้นที่คงที่ ERP ที่รู้จักหน่วยเดียวต่อรายการสินค้าจะบังคับให้ผู้ใช้
ต้องแต่งตัวเลขขึ้นมาเอง ไม่น้ำหนักก็จำนวนชิ้น ส่วนการจัดการ catch-weight เต็มรูปแบบ — ทุกการเคลื่อนไหวมีจำนวนสองค่า
ที่เป็นอิสระต่อกัน พร้อมค่าที่ยอมรับได้รายชิ้นและการตั้งราคาในหน่วยใดหน่วยหนึ่งก็ได้ — มีขนาดใหญ่จน ERP รายใหญ่ส่งมอบเป็น
โมดูลแยกต่างหาก

การเพิ่มจำนวนค่าที่สองเข้าไปในบัญชีเคลื่อนไหวแบบ append-only ภายหลังมีต้นทุนสูงเป็นพิเศษ: รายการเคลื่อนไหวในอดีต
แก้ไขไม่ได้ (ADR-0003) จึงจะขาดค่านี้ไปตลอดกาล

## การตัดสินใจ

1. **ทุกรายการสินค้ามีหน่วยหลักหนึ่งหน่วยพอดี** ซึ่งใช้ตีมูลค่าและคำนวณยอดคงเหลือ (kg สำหรับไก่ทั้งตัว, ชิ้นสำหรับน่องไก่)
2. **หน่วยซื้อแปลงเป็นหน่วยหลักด้วยตัวคูณคงที่** ต่อรายการสินค้า (ลัง → kg)
3. **รายการสินค้ากำหนดให้เป็นรายการน้ำหนักแปรผันได้** สำหรับรายการเหล่านี้ การรับสินค้าและการผลิตจะบันทึก**ทั้ง**น้ำหนัก
   จริงในหน่วยหลัก**และ**จำนวนชิ้นเป็น**จำนวนหน่วยที่สอง** ERP คำนวณน้ำหนักเฉลี่ยต่อชิ้นต่อ lot เพื่อใช้ในการวางแผน
   การตีมูลค่าใช้หน่วยหลักเสมอ
4. **schema มีจำนวนหน่วยที่สองตั้งแต่วันแรก** ทั้งบน lot และรายการเคลื่อนไหว (nullable) แม้ว่าใน v1 จะมีเพียงการรับ
   สินค้าและการผลิตที่ใช้ค่านี้
5. **การขายแบบชั่งน้ำหนักบน POS ได้รับการรองรับอย่างเต็มรูปแบบ** POS ขายรายการเมนูตามน้ำหนักได้อยู่แล้ว บรรทัดการขาย
   แบบชั่งน้ำหนักจะส่งมาพร้อมน้ำหนัก และสูตรเมนูสามารถกำหนดการใช้วัตถุดิบต่อกิโลกรัมที่ขายได้

## ผลที่ตามมา

- เส้นทางของไก่ทำงานได้โดยไม่มีใครต้องแต่งตัวเลขขึ้นมา: รับเข้า 21.6 kg เป็นไก่ 12 ตัว ผลิตชิ้นส่วนพร้อมน้ำหนักผลผลิต
  ที่ชั่งจริง ขายเป็นชิ้นหรือตามน้ำหนัก
- สิ่งที่เลื่อนออกไป: ค่าที่ยอมรับได้ของน้ำหนักรายชิ้น ราคาที่เสนอต่อหน่วยที่สอง และจำนวนหน่วยที่สองในการโอนและการใช้
  ที่สาขา ทั้งหมดนี้เพิ่มได้ภายหลังโดยไม่ต้อง migrate ข้อมูลในอดีต

## ทางเลือกที่พิจารณา

- **หน่วยเดียวต่อรายการสินค้า ไม่มีอย่างอื่น** ปฏิเสธสำหรับการใช้งานจริง: ผู้ใช้จะต้องปลอมน้ำหนักหรือจำนวนอย่างใด
  อย่างหนึ่ง และบัญชีเคลื่อนไหวจะบันทึกเรื่องแต่งนั้นไว้
- **catch-weight เต็มรูปแบบในรุ่นแรก** ปฏิเสธ: เพิ่มความซับซ้อนของเอกสารทุกฉบับเป็นเท่าตัว เพื่อประโยชน์ที่รุ่นแรกไม่ต้องการ
