# ADR-0016: ExcelToGo เข้าร่วมระบบนิเวศในฐานะเครื่องมือสเปรดชีต

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-26
- **English:** [0016-exceltogo-spreadsheet-companion.md](0016-exceltogo-spreadsheet-companion.md)

## บริบท

มีสองเรื่องที่ขวางระหว่าง ERP นี้กับเชนจริง (ADR-0012 ระดับ 2) และทั้งสองเรื่องอยู่ในสเปรดชีต:

- **การย้ายข้อมูลตอนเริ่มใช้** เชนมาพร้อมรายการสินค้า หน่วยนับ สูตร BOM par level และยอดยกมาใน Excel ถ้าไม่มีทาง
  นำเข้าที่ดี ก็ไม่มีใครย้ายมา
- **รายงานของฝ่ายบัญชี** ฝ่ายบัญชีทำงานใน Excel และจะทำต่อไป อยากได้มูลค่าสต๊อก ต้นทุนการใช้ และส่วนต่าง ในที่ที่สูตร
  ของตัวเองอยู่

[ExcelToGo](https://github.com/SuruchBoss/ExcelToGo) เป็นเว็บแอปสเปรดชีต Apache 2.0 ของเจ้าของเดียวกัน เปิด `.xlsx`
แล้วหน้าตาเหมือนเดิม อ่านไฟล์ที่ล็อกไว้เป็นแม่แบบให้กรอก ปฏิเสธค่าที่ผิดก่อนเขียนลงเซลล์ เก็บชีตไว้ในเบราว์เซอร์ และดึงข้อมูล
จาก REST API เข้าเซลล์ผ่านเซิร์ฟเวอร์ของตัวเองได้ (ไล่หน้า รู้จัก rate limit และเข้ารหัส credential ที่เก็บไว้) ExcelToGo
ถูกชวนเข้าระบบนิเวศและตอบรับแล้ว PO ของ ExcelToGo ตรวจทุกข้อที่อ้างถึงกับโค้ดจริง และแก้ข้อเท็จจริงสองข้อ ซึ่งสะท้อนอยู่
ในการตัดสินใจด้านล่าง

## การตัดสินใจ

1. **ExcelToGo คือเครื่องมือสเปรดชีตของระบบนิเวศ** และยังเป็นผลิตภัณฑ์ที่ยืนเองได้ตามกติกาของตัวเอง ("อยู่ทุกที่ แต่
   ไม่จำเป็นที่ไหนเลย") ไม่มีอะไรที่เป็นของ PaynEat โผล่ขึ้นมา จนกว่าจะมีคนเปิดแม่แบบของ ERP หรือตั้งค่าแหล่งข้อมูล ERP
   รุ่นของระบบตาม ADR-0015 ใช้กับ ERP ไม่ใช้กับ ExcelToGo
2. **การย้ายข้อมูลส่งกันเป็นไฟล์ ไม่ใช่ API call**
   - **ERP เป็นเจ้าของแม่แบบนำเข้า:** ชีต คอลัมน์ กฎ และชีตอ้างอิงที่ซ่อนและล็อกไว้ (หน่วย รหัสสถานที่ รหัสสินค้า)
     ซึ่ง ERP สร้างจาก master data ปัจจุบัน
   - คนกรอกแม่แบบใน ExcelToGo (หรือใน Excel) ดาวน์โหลด `.xlsx` แล้วอัปโหลดเข้า ERP **ERP ตรวจซ้ำทุกแถว**
     และแจ้งข้อผิดพลาดเป็นรายแถว ไม่เชื่อไฟล์
   - ExcelToGo จึงไม่ถือ token ของ ERP ที่มีสิทธิ์เขียน และชีตไม่ออกจากเบราว์เซอร์ การส่งข้อมูลจาก ExcelToGo เข้า
     ERP ตรงๆ ถือเป็นการตัดสินใจใหม่
   - ชีตอ้างอิงใช้รหัสของระบบนิเวศตรงตามที่ ERP ออกให้ ไม่มีใครแปลงรหัส
3. **รายงานอ่านจาก public API แบบ polling** ExcelToGo เป็นผู้ใช้รายแรกของ public API ตาม ADR-0013 และไม่รับ
   webhook ดังนั้น**ทุกอย่างที่รายงานต้องใช้ต้องอ่านได้ผ่าน API** ไม่ใช่มีเฉพาะทาง webhook API ถูกออกแบบให้เข้ากับตัวไล่
   หน้าที่ ExcelToGo มีอยู่แล้ว:
   - คำตอบแบบรายการเป็น `{ "data": [...], "next": "<URL เต็มบน host เดียวกัน>" }` และ `next: null` ที่หน้าสุดท้าย
   - เมื่อจำกัด rate ให้ตอบ `429` พร้อม `Retry-After` เป็นวินาที
   - endpoint แบบรายการรับขนาดหน้าได้อย่างน้อย 2,500 แถว
   - ทุกคำขอมี `x-request-id` ของตัวเอง (`TELEMETRY.md`)
4. **ข้อมูลรายงานมี scope แคบ** แหล่งข้อมูลของ ExcelToGo เป็นของทั้ง deployment: audit trail ของ ERP เห็นแค่ว่า
   integration เรียก ไม่เห็นว่านักบัญชีคนไหนขอ และทุกคนที่ถือ operator token ของ deployment นั้นเห็นสิ่งที่ดึงมา
   endpoint รายงานจึงมี **scope ของตัวเอง แยกตามความอ่อนไหว** (เช่น จำนวนสต๊อกแยกจากต้นทุนและมูลค่า) แคบกว่า
   `items:read` และคู่มือติดตั้งเขียนเรื่องนี้ไว้ตรงๆ เชนจะได้ไม่ต้องค้นพบเอง
5. **ห้ามแตะฐานข้อมูลของ ERP** ExcelToGo ต่อ PostgreSQL ตรงได้ แต่การใช้กับ ERP เป็นสิ่งต้องห้าม (ADR-0013)
   ExcelToGo บังคับข้อนี้ด้วยโค้ดไม่ได้ เพราะรายชื่อ host เป็นของ operator ฝั่ง ERP จึงกันอีกชั้น: คู่มือติดตั้งผูก
   ฐานข้อมูลของ ERP ไว้กับเครือข่ายของ ERP เอง และใช้ role ของฐานข้อมูลที่รับเฉพาะแอป ERP
6. **รูปแบบการติดตั้ง** ERP คือ**เซิร์ฟเวอร์กลางหนึ่งเครื่องต่อหนึ่งเชน ติดตั้งเอง** จะอยู่ในเครือข่ายภายในของเชน หรือบน
   VM ในคลาวด์ก็ได้ รองรับทั้งสองแบบ ExcelToGo สำหรับงานนี้ก็ติดตั้งเองเช่นกัน (demo สาธารณะเก็บแหล่งข้อมูลไม่ได้)
   การเข้าถึง ERP ในเครือข่ายภายในเป็นการตัดสินใจของ ExcelToGo ซึ่งเลือกให้ operator ระบุ host ภายในทีละชื่อแบบ
   ตรงตัว และยังบล็อก loopback, link-local และที่อยู่ metadata เสมอ นี่เป็นการตัดสินใจ ยังไม่ใช่ความสามารถที่มีแล้ว
   คู่มือติดตั้งจะอ้างถึงก็ต่อเมื่อ ExcelToGo ยืนยันว่าทำเสร็จแล้ว (ข้อ 7)
7. **จังหวะเวลา:**
   - แม่แบบนำเข้า: ออกแบบตอนนี้ สร้าง**หลัง v1 และก่อนเชนนำร่องเริ่มใช้** ฝั่ง ExcelToGo มีงานแก้ของตัวเองก่อน
     (การอ้างช่วงเซลล์ข้ามชีตในกฎ list และการ round-trip)
   - รายงานข้อมูลสด: หลังจาก public API มีแล้ว **และ** หลัง PO ของ ExcelToGo ยืนยันว่าฝั่งตัวเองพร้อม ERP จะไม่เปิด
     การเชื่อมต่อนี้ก่อน
   - `x-request-id` จาก ExcelToGo: ทำได้ทุกเมื่อ

## ผลที่ตามมา

- ERP ได้ทางย้ายข้อมูลและทางทำรายงานโดยไม่ต้องสร้างสเปรดชีตเอง และการทดสอบจริงครั้งแรกของ "ต่อยอดจากข้างนอก" ใน
  ADR-0013 เป็นผลิตภัณฑ์จริง ไม่ใช่ตัวอย่าง
- public API มีผู้ใช้รายแรกก่อนจะออกแบบ การแบ่งหน้าและ rate limit จึงถูกเลือกครั้งเดียวโดยเทียบกับโค้ดจริง
- แม่แบบฉบับร่างและตัวสร้างอยู่ที่ `docs/integrations/exceltogo/` เป็นตัวอย่างสำหรับออกแบบ ยังไม่ใช่สัญญา จนกว่า
  ticket ของตัวนำเข้าจะกำหนดรูปแบบจริง
- รายการ scope ของ public API ต้องมี scope รายงานที่แยกตามความอ่อนไหว
- คู่มือติดตั้งต้องมีเรื่องการผูกฐานข้อมูลในข้อ 5 และข้อควรระวังเรื่อง token ในข้อ 4

## ทางเลือกที่พิจารณาแล้ว

- **สร้างหน้านำเข้าแบบสเปรดชีตใน ERP เอง** ปฏิเสธ: ลงแรงมากกับสิ่งที่ ExcelToGo และ Excel ทำได้อยู่แล้ว และก็ยัง
  ไม่ใช่ที่ที่ฝ่ายบัญชีทำงาน
- **ให้ ExcelToGo เรียก endpoint นำเข้าของ ERP ตรง** เลื่อนไปก่อน: ต้องใช้ token ที่มีสิทธิ์เขียนในแหล่งข้อมูลที่เป็นของ
  ทั้ง deployment และทำให้ข้อมูลชีตออกจากเบราว์เซอร์ ทางไฟล์รักษาได้ทั้งสองข้อ
- **ส่ง webhook ไปหา ExcelToGo** ปฏิเสธในตอนนี้: ExcelToGo ไม่มีตัวรับ และรายงานรีเฟรชเมื่อผู้ใช้สั่ง
- **อ่านฐานข้อมูลของ ERP เพื่อทำรายงาน** ปฏิเสธโดย ADR-0013
