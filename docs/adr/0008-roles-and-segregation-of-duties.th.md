# ADR-0008: บทบาทและการแยกหน้าที่

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-25
- **English:** [0008-roles-and-segregation-of-duties.md](0008-roles-and-segregation-of-duties.md)

## บริบท

ใน ERP การควบคุมขั้นพื้นฐานที่สุดที่ผู้ตรวจสอบบัญชีตรวจคือ คนที่ผูกมัดบริษัทให้ต้องจ่ายเงิน หรือคนที่ตัดจำหน่ายสต๊อก
ต้องไม่ใช่คนเดียวกับผู้อนุมัติ บทบาทเพียงอย่างเดียวรับประกันเรื่องนี้ไม่ได้: เครือร้านขนาดเล็กมักให้คนคนเดียวถือหลายบทบาท

## การตัดสินใจ

1. **บทบาทเจ็ดบทบาทใน v1:**

   | บทบาท | ทำอะไรได้ |
   |---|---|
   | `admin` | จัดการผู้ใช้ บทบาท สถานที่เก็บสต๊อก การตั้งค่า; เปิดงวดที่ปิดแล้วอีกครั้ง |
   | `purchasing` | สร้างและส่งใบสั่งซื้อ; จัดการซัพพลายเออร์ |
   | `purchasing_approver` | อนุมัติใบสั่งซื้อที่เกินเกณฑ์วงเงินที่ต้องอนุมัติ |
   | `plant` | รับสินค้า ดำเนินการใบสั่งผลิต จัดการสต๊อกของโรงงาน |
   | `logistics` | ส่งของ (dispatch) ตามใบโอน |
   | `branch_manager` | ออกใบขอเบิก รับโอน ตรวจนับสต๊อกสาขา |
   | `finance` | ดูต้นทุน ส่วนต่าง และมูลค่าสต๊อก; export ข้อมูลทางการเงิน |

2. **ผู้ใช้หนึ่งคนถือหลายบทบาทได้**
3. **ไม่มีใครอนุมัติเอกสารที่ตัวเองสร้างได้** ไม่ว่าจะถือบทบาทใดอยู่ก็ตาม ข้อนี้ใช้กับใบสั่งซื้อที่เกินเกณฑ์วงเงิน การรับ
   สินค้าที่อยู่นอกค่าที่ยอมรับได้ ใบปรับยอดจากการตรวจนับสต๊อก และการตัดจำหน่าย การตรวจสอบนี้บังคับใช้ในชั้นเซอร์วิส
   (service layer) ทุกครั้งที่มีการอนุมัติ ไม่ใช่แค่ซ่อนไว้ใน UI
4. **ทุกการ post และทุกการอนุมัติบันทึกว่าใครทำและทำเมื่อไร** (ADR-0003)

## ผลที่ตามมา

- การทดลองใช้งานนำร่องที่มีผู้ใช้คนเดียวต้องมีบัญชีที่สองไว้อนุมัติทุกอย่างที่ต้องอนุมัติ ข้อนี้ตั้งใจให้เป็นเช่นนั้น: นี่คือ
  การควบคุมที่กำลังทำงานอยู่
- เกณฑ์ต่างๆ (เช่น มูลค่าใบสั่งซื้อที่ต้องขออนุมัติ) เป็นการตั้งค่า ไม่ใช่โค้ด

## ทางเลือกที่พิจารณา

- **ตรวจสิทธิ์ตามบทบาทอย่างเดียว** ปฏิเสธ: ผู้ใช้หนึ่งคนที่ถือทั้งสองบทบาทจะสร้างและอนุมัติใบสั่งซื้อของตัวเองได้
- **workflow ที่ตั้งค่าได้พร้อมการอนุมัติหลายระดับใน v1** เลื่อนออกไป: การอนุมัติขั้นเดียวพร้อมการแยกหน้าที่คือการควบคุม
  ที่สำคัญ workflow หลายระดับเพิ่มสิ่งที่ต้องตั้งค่าโดยไม่ได้เพิ่มการควบคุมชนิดใหม่
