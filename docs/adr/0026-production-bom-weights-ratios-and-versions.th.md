# ADR-0026: สูตรการผลิต (BOM): น้ำหนัก สัดส่วนปันต้นทุนตั้งต้น ของเสีย และเวอร์ชัน

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-10
- **English:** [0026-production-bom-weights-ratios-and-versions.md](0026-production-bom-weights-ratios-and-versions.md)

## บริบท

ADR-0004 กำหนดว่าใบสั่งผลิตแบ่งต้นทุนวัตถุดิบให้ผลผลิตตามสัดส่วนปันต้นทุน (allocation ratio) และสัดส่วนนั้นมาจาก BOM
โดยค่าตั้งต้นคือสัดส่วนน้ำหนักผลผลิตที่คาดไว้ของแต่ละรายการ แต่พอสร้างสูตรการผลิต (#12) ยังมีคำถามที่การตัดสินใจนั้นไม่ได้ตอบ:

- ผลผลิตนับคนละหน่วย ชิ้นไก่นับเป็นชิ้น โครงไก่นับเป็นกิโลกรัม ผลผลิตที่นับเป็นชิ้นมี "น้ำหนัก" อะไร
- สัดส่วนตั้งต้นปัดเศษอย่างไรให้รวมได้ 100% พอดี
- ผู้ดูแลระบบกำหนดสัดส่วนเองได้แค่ไหน
- ของเสีย คือน้ำหนักที่เข้าไปแต่ไม่ออกมาเป็นผลผลิต จะเป็นอย่างไร
- จะเปลี่ยน BOM อย่างไรโดยไม่เปลี่ยนสิ่งที่ใบสั่งผลิตใช้ไปแล้ว
- BOM เป็นข้อมูลหลักที่ POS ทุกเครื่องต้องดึงไปด้วยหรือไม่

## การตัดสินใจ

1. **ทุกปริมาณเทียบกันด้วยน้ำหนักเป็นกิโลกรัม** บรรทัดที่นับเป็น kg หนักเท่าปริมาณ บรรทัดที่นับเป็น g หนักหนึ่งในพันของปริมาณ
   บรรทัดที่นับด้วยหน่วยอื่น (ชิ้น ลิตร แพ็ก) ต้องระบุน้ำหนักที่คาดไว้ต่อรอบการผลิต ทั้งวัตถุดิบและผลผลิต ส่วนบรรทัด kg หรือ g ไม่ต้องระบุ
   น้ำหนักเก็บละเอียดถึงกรัม
2. **สัดส่วนปันต้นทุนตั้งต้นของผลผลิตคือสัดส่วนน้ำหนักผลผลิตที่คาดไว้ เป็นเปอร์เซ็นต์ละเอียด 0.01%** ตัดแต่ละสัดส่วนลงเหลือ 0.01%
   แล้วแจก 0.01% ที่ยังขาดทีละหน่วยให้ผลผลิตที่ถูกตัดทิ้งมากที่สุดก่อน ถ้าเท่ากันให้บรรทัดที่มาก่อน (largest remainder)
   สัดส่วนจึงรวมได้ 100.00 พอดีเสมอ
3. **ผู้ดูแลระบบกำหนดสัดส่วนเองได้ ต้องกำหนดทุกรายการหรือไม่กำหนดเลย** แต่ละสัดส่วนต้องมากกว่าศูนย์ ไม่เกิน 100
   ทศนิยมไม่เกินสองตำแหน่ง และรวมกันได้ 100.00 พอดี แต่ละเวอร์ชันเก็บสัดส่วนที่ใช้แบ่งต้นทุนไว้ พร้อมบอกว่ากำหนดเองหรือไม่
   สัดส่วนตั้งต้นจะคำนวณใหม่ทุกครั้งที่แก้ปริมาณของเวอร์ชัน
4. **ของเสียคือน้ำหนักวัตถุดิบลบน้ำหนักผลผลิตที่คาดไว้ และไม่มีสัดส่วนปันต้นทุน** ต้นทุนส่วนนั้นตกอยู่กับผลผลิต
   เวอร์ชันที่คาดว่าผลผลิตหนักกว่าวัตถุดิบจะถูกปฏิเสธ เพราะการผลิตหนึ่งรอบไม่มีทางได้น้ำหนักเพิ่ม
5. **สินค้าหนึ่งรายการอยู่ได้ไม่เกินหนึ่งบรรทัดต่อฝั่ง และอยู่ทั้งสองฝั่งไม่ได้** การผลิตไม่ใช้ของที่ตัวเองผลิต
6. **BOM มีเวอร์ชันตามวันที่มีผล ด้วยกฎเดียวกับที่ ADR-0023 ใช้กับสูตรอาหาร** เวอร์ชันมีผลตั้งแต่วันทำการที่เริ่มมีผลจนกว่าเวอร์ชันถัดไปจะเริ่ม
   เวอร์ชันใหม่เริ่มได้วันนี้ถ้ายังไม่มีเวอร์ชันที่มีผล ไม่อย่างนั้นเร็วสุดพรุ่งนี้ และห้ามเริ่มวันเดียวกับเวอร์ชันอื่น
   เวอร์ชันที่มีผลแล้วไม่เปลี่ยนอีก ส่วนเวอร์ชันที่ยังไม่เริ่มแก้ได้ ใบสั่งผลิต (#13) บันทึกเวอร์ชันที่ใช้ไว้
7. **BOM เป็นการตั้งค่า ไม่ใช่ข้อมูลหลัก** การเปลี่ยนแปลงบันทึกใน audit แต่ไม่ใช้ master data version POS จึงไม่ได้รับ BOM
   และสัญญากับ POS ไม่เปลี่ยน มีแค่ `admin` ที่แก้ BOM ได้ ส่วน `plant` และ `finance` อ่านได้ (ADR-0008)
8. **เวอร์ชันแรกของระบบให้โรงงานเป็นผู้ผลิต** BOM ระบุประเภทสถานที่ที่ผลิต และรับได้แค่ `plant`

## ผลที่ตามมา

- ตัวอย่างไก่ทั้งตัวของ #12 ตรวจด้วยมือได้: วัตถุดิบ 20 กก. คาดว่าได้ชิ้นไก่และโครงไก่ 18 กก. ของเสีย 2 กก. อัตราผลได้ 90%
  สัดส่วนตั้งต้น 27.78 / 20.00 / 15.56 / 12.22 / 24.44
- สัดส่วนที่ใบสั่งผลิตใช้แบ่งต้นทุนถูกตรึงไว้กับเวอร์ชันที่ใช้ การแก้ BOM ภายหลังจึงไม่ทำให้ต้นทุนของรอบที่ผลิตเสร็จแล้วเปลี่ยน
- ผลผลิตที่นับเป็นชิ้นต้องมีคนคอยปรับน้ำหนักที่คาดไว้ให้ทันสมัย โรงงานจะเห็นน้ำหนักจริงในใบสั่งผลิต (#13)
  และแก้ BOM ได้ด้วยเวอร์ชันใหม่
- console import โค้ดของ backend ไม่ได้ (ADR-0021) จึงขอให้ API คำนวณตัวอย่างของเวอร์ชันระหว่างที่พิมพ์
  (`POST /production-boms/preview`) แบบเดียวกับใบรับสินค้า กฎจึงมีอยู่ที่เดียว

## หมายเหตุแก้ไข (2026-10-10, #69)

ข้อนี้เพิ่มการตรวจหนึ่งข้อ ไม่ได้เปลี่ยนความหมายของการตัดสินใจข้างบน

- ข้อ 2 อาจตัดสัดส่วนของผลผลิตที่เบามากเหลือ 0.00% ได้ (1 กรัมเทียบกับ 50 กก. คือ 0.0019999% และ largest remainder
  ให้ 0.01 ที่ขาดไปกับผลผลิตที่หนักกว่า) ขณะที่ข้อ 3 ปฏิเสธสัดส่วนศูนย์เฉพาะตอนกำหนดเอง เวอร์ชันที่สัดส่วน**ตั้งต้น**
  ทำให้ผลผลิตใดได้ 0.00 จึงถูกปฏิเสธด้วย (`default_ratio_zero`) พร้อมบอกบรรทัดผลผลิตนั้น ใบสั่งผลิตจะได้ไม่ปันต้นทุนศูนย์ให้ lot
  ใดโดยไม่มีใครเลือก ผู้ดูแลระบบกำหนดสัดส่วนเอง หรือแก้น้ำหนักที่คาดไว้
- สัดส่วนที่กำหนดเองไม่ได้รับผล เพราะปฏิเสธศูนย์อยู่แล้ว เวอร์ชันที่บันทึกก่อนการตรวจนี้ไม่ถูกตรวจซ้ำ

## ทางเลือกที่พิจารณา

- **แบ่งตามจำนวนผลผลิต หรือตามมูลค่าขาย** ไม่ใช้เป็นค่าตั้งต้น เพราะ ADR-0004 เลือกสัดส่วนน้ำหนัก และมูลค่าขายต้องใช้ราคาที่โรงงานไม่มี
  การกำหนดสัดส่วนเองรองรับเครือร้านที่อยากให้อกไก่รับต้นทุนมากกว่าโครงไก่ได้อยู่แล้ว
- **ปัดเศษแต่ละสัดส่วนแยกกันแบบปัดครึ่งขึ้น** ไม่ใช้ เพราะสัดส่วนจะรวมได้ 99.99 หรือ 100.01 และต้นทุนของรอบการผลิตจะแบ่งไม่ครบ
- **ให้ของเสียมีสัดส่วนของตัวเอง** ไม่ใช้ เพราะของเสียไม่ใช่สต๊อกและไม่มี lot ไหนรับไป ต้นทุนต้องตกอยู่กับผลผลิต
- **ให้ผลผลิตที่นับเป็นชิ้นไม่มีน้ำหนักและไม่นับในค่าตั้งต้น** ไม่ใช้ เพราะผลผลิตที่มีค่าที่สุด (อก สะโพก) นับเป็นชิ้น จะไม่ได้รับต้นทุนเลย
