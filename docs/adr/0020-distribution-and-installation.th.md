# ADR-0020: การแจกจ่ายและการติดตั้ง: console ที่ติดตั้งลงเครื่องได้ เซิร์ฟเวอร์ที่เชนติดตั้งเองได้โดยไม่ต้องมีนักพัฒนา และ PaynEat Cloud ในภายหลัง

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-26
- **English:** [0020-distribution-and-installation.md](0020-distribution-and-installation.md)

## บริบท

ทุกวันนี้การติดตั้ง ERP ต้อง clone repository แล้วรันคำสั่ง ซึ่งพอใช้สำหรับคนที่มาประเมินโปรเจกต์ แต่ใช้ไม่ได้เลยกับเชนร้านอาหาร
ไม่มีใครในเชนจะรัน `git pull` หรือ `npm run` เป้าหมายระดับ 2 ของ ADR-0012 ("ใช้งานจริงในหลายเชน") จะไปไม่ถึง จนกว่าเชนจะ
ติดตั้ง เปิดใช้ และอัปเกรด ERP ได้เองโดยไม่ต้องมีนักพัฒนา

มีสองเรื่องที่ต้องทำให้ง่าย และคำตอบของสองเรื่องนี้ต่างกัน:

- **หน้าจอที่คนใช้**: บน PC ที่สำนักงานใหญ่ แท็บเล็ตในโรงงาน และมือถือที่ประตูหลังร้าน ตอนนี้ console เป็นเว็บแอปเดียว
  ที่ใช้ได้ทุกขนาดจออยู่แล้ว (#34)
- **เซิร์ฟเวอร์**: เซิร์ฟเวอร์กลางหนึ่งเครื่องต่อหนึ่งเชน (ADR-0016 ข้อ 6) พร้อม PostgreSQL การสำรองข้อมูล และการอัปเกรด
  เรื่องนี้ยากกว่า และเป็นตัวตัดสินว่าเชนจะใช้ ERP ได้หรือไม่

ADR-0015 ระบุไว้แล้วว่าบริการ hosting ("PaynEat Cloud") เป็นบริการเสียเงิน และแอปมือถือเฉพาะสำหรับรับของ ตรวจนับ และส่งของ
เป็นผู้สมัครของรุ่น Enterprise ADR นี้วางเรื่องการแจกจ่ายไว้คู่กับทั้งสองเรื่องนั้นโดยไม่ขัดกัน

## การตัดสินใจ

1. **console ติดตั้งลงเครื่องได้แบบ Progressive Web App ตั้งแต่ v1** ผู้ใช้เปิดที่อยู่ ERP ของเชน แล้วติดตั้งจาก browser ลง
   Android, iPhone, iPad, Windows หรือ macOS แอปจะเปิดเต็มจอพร้อมไอคอน PaynEat ERP ใช้โค้ดชุดเดียวกันและ release
   เดียวกันทุกเครื่อง และอัปเดตพร้อมเซิร์ฟเวอร์
   - service worker เก็บ cache **เฉพาะตัวแอป** (HTML, script, style, ไอคอน) **ไม่เก็บ cache ของ response จาก API เด็ดขาด**
     ตัวเลขสต๊อกที่มาจาก cache คือตัวเลขเก่าที่แสดงเหมือนเป็นตัวเลขปัจจุบัน เมื่อออฟไลน์ console จะบอกว่าไม่มีการเชื่อมต่อ
     และไม่แสดงข้อมูลเก่า
   - console ที่ติดตั้งลงเครื่องได้เป็นของ **Community** เพราะก็คือ console ของ Community ที่ถูกติดตั้ง ส่วนแอป native เฉพาะที่
     รับของ ตรวจนับ และสแกนได้แบบออฟไลน์ ยังเป็นผู้สมัครของ Enterprise ตาม ADR-0015 ข้อ 4
2. **เซิร์ฟเวอร์ติดตั้งได้โดยไม่ต้องมีนักพัฒนา ทำทีละขั้น** (ทางเลือก "D"):
   1. **หลัง v1 ก่อนเชนนำร่อง** (Community ทั้งหมด เพราะการติดตั้ง การสำรองข้อมูล และการอัปเกรดไม่มีวันอยู่หลัง paywall
      ตาม ADR-0015 ข้อ 3):
      - **การตั้งค่าครั้งแรกใน console** เมื่อฐานข้อมูลยังว่าง console จะพา admin ตั้งค่าบริษัท บัญชี admin คนแรกพร้อมการยืนยัน
        ตัวตนขั้นที่สอง และสถานที่แรกๆ ไม่ต้องใช้ command line และไม่ใช้ seed เดโม (ADR-0015, #5)
      - **ตัวติดตั้งคำสั่งเดียว และ image เซิร์ฟเวอร์สำเร็จรูป** สำหรับ VM บนคลาวด์ และสำหรับเครื่องในเครือข่ายของเชนเอง
        ตั้งค่าการสำรองข้อมูลอัตโนมัติให้ และอัปเกรดได้จากปุ่มใน console โดยใช้ขั้นตอนการอัปเกรดที่ผ่านการทดสอบ (#28)
      - **แอป Android บน Google Play** ที่ห่อ console ที่ติดตั้งได้ (Trusted Web Activity) ถ้าเชนนำร่องต้องการ แอปจะถามที่อยู่ ERP
        ของเชนตอนเปิดครั้งแรก
   2. **หลังเชนนำร่อง:**
      - **PaynEat Cloud** บริการ hosting แบบเสียเงินตาม ADR-0015 ข้อ 5 เป็นซอฟต์แวร์ Community ชุดเดียวกัน โดยเราดูแลให้
        สำหรับเชนที่ไม่มีทีมไอที
      - **แอป iOS บน App Store** เฉพาะเมื่อเชนต้องการจริง Apple มักปฏิเสธแอปที่แค่ห่อเว็บไว้ จึงต้องมีเหตุผลแบบ native ที่ชัดเจน
      - เดโมออนไลน์สาธารณะ
3. **การติดตั้งเองยังเป็นค่าเริ่มต้นและรองรับเสมอ** (ADR-0016 ข้อ 6 ถูกขยาย ไม่ได้ถูกแทนที่) เชนที่ใช้ PaynEat Cloud
   export ข้อมูลทั้งหมดแล้วย้ายไปเซิร์ฟเวอร์ของตัวเองได้ทุกเมื่อ และเชนที่ติดตั้งเองก็ย้ายขึ้นคลาวด์ได้ ซอฟต์แวร์ รูปแบบข้อมูล
   และขั้นตอนอัปเกรดเหมือนกันทั้งสองแบบ
4. **ไม่มีตัวติดตั้งเซิร์ฟเวอร์แบบ Windows (`.exe`)** PC ที่สำนักงานใหญ่ถูกปิด ถูกอัปเดต และถูกเปลี่ยนเครื่องโดยคนที่ไม่รู้ว่าเครื่อง
   นั้นเก็บบัญชีของทั้งเชน เชนที่มีแต่ Windows ให้รัน image เซิร์ฟเวอร์ใน VM หรือใช้ PaynEat Cloud แต่ PC Windows ยังเป็น
   *เครื่องใช้งาน* ที่ดี เพราะติดตั้ง console จาก browser ได้ (ข้อ 1)
5. **การแจกจ่าย PaynEat POS เป็นการตัดสินใจของ POS เอง** POS เป็นแอป Flutter ที่ build ลง Android, iOS และ Windows ได้อยู่แล้ว
   และทำงานในร้าน การขึ้น store ของ POS ตัดสินใน repository ของ POS

## ผลที่ตามมา

- v1 มี ticket เพิ่มหนึ่งใบที่งานไม่มาก (console ที่ติดตั้งลงเครื่องได้) และยังคงขอบเขต 6 สัปดาห์ไว้
- ลำดับงานหลัง v1 ใน #1 มี "ติดตั้งได้โดยไม่ต้องมีนักพัฒนา" เป็นเงื่อนไขก่อนเริ่มเชนนำร่อง คู่กับแม่แบบนำเข้าข้อมูล
- การให้บริการ PaynEat Cloud ทำให้เราต้องรับผิดชอบเซิร์ฟเวอร์ การสำรองข้อมูล ความปลอดภัย และข้อมูลส่วนบุคคล (PDPA)
  ของเชนอื่น จึงเริ่มหลังจากเชนนำร่องแสดงให้เห็นว่าการดูแลมีต้นทุนเท่าไร
- เชนไม่ถูกผูกมัดกับเรา การย้ายออกจากคลาวด์คือการ export และการติดตั้ง ซึ่งมีเอกสารทั้งสองอย่าง

## ทางเลือกที่พิจารณาแล้ว

- **ทำแอป native ทุกแพลตฟอร์มตอนนี้** ไม่เลือก: ต้องดูแลโค้ดหลายชุดและผ่านการรีวิวของหลาย store สำหรับหน้าจอที่ใช้ได้ใน
  ทุก browser อยู่แล้ว ทั้งที่ยังไม่มีเชนไหนใช้งาน
- **ตัวติดตั้งเซิร์ฟเวอร์แบบ `.exe` บน Windows** ไม่เลือก ด้วยเหตุผลในข้อ 4
- **คลาวด์อย่างเดียว (ไม่มีการติดตั้งเอง)** ไม่เลือก: ขัดกับ ADR-0016 และกับสัญญาของ ADR-0015 ว่าเชนเข้าถึงและเก็บข้อมูลของ
  ตัวเองได้เสมอ และบางเชนจะต้องการให้ข้อมูลอยู่ในเครือข่ายของตัวเอง
- **ติดตั้งเองอย่างเดียว ด้วยมือ** ไม่เลือก: ทำให้เชนที่ไม่มีทีมไอทีใช้ ERP ไม่ได้ ซึ่งคือเชนส่วนใหญ่
