# ADR-0030: การใช้วัตถุดิบที่สาขา: เอกสารหนึ่งใบต่อยอดขาย lot แทน ยอดขายที่ถูกพัก และบัญชีอัตโนมัติ

- **สถานะ:** Proposed
- **วันที่:** 2026-10-10
- **English:** [0030-branch-consumption-placeholder-lots-and-held-sales.md](0030-branch-consumption-placeholder-lots-and-held-sales.md)

## บริบท

ADR-0002 ตัดสินว่า ERP เปลี่ยน sales event ที่ POS ส่งมาให้เป็นการใช้วัตถุดิบที่สาขา โดยแตกตามสูตรที่ใช้อยู่
ณ เวลาขาย ADR-0003 ตัดสินว่าสาขาติดลบได้และไม่ปฏิเสธยอดขายเพราะสต๊อก ADR-0004 ตัดสินว่าการใช้วัตถุดิบใช้
ต้นทุนของ lot ที่ตัด และ ADR-0006 ตัดสินว่าตัด lot แบบหมดอายุก่อนออกก่อน (FEFO) เมื่อสร้างจริง (#17)
ยังมีคำถามที่การตัดสินเหล่านั้นไม่ได้ตอบ:

- เมื่อ lot ที่ใช้ได้ของสาขาไม่พอสำหรับยอดขาย lot ไหนจะติดลบ และถ้าสาขาไม่เคยมีสินค้านั้นเลย จนไม่มี lot
  ให้ติดลบล่ะ
- แท็บเล็ต POS ที่นาฬิกาผิดอาจลงเวลาขายล่วงหน้าไปหนึ่งวันหรือหนึ่งปี ถ้าลงบัญชีตามนั้น การใช้วัตถุดิบจะไปอยู่
  ในงวดที่ไม่มีใครดู
- ทุกรายการในบัญชีสต๊อกต้องระบุผู้บันทึก แต่ตัวประมวลผลทำงานโดยไม่มีใครล็อกอิน
- ยอดขายที่เมนู ตัวเลือกเสริม หรือวัตถุดิบผิด จะเป็นการใช้วัตถุดิบไม่ได้จนกว่าจะมีคนแก้ข้อมูลหลัก อะไรที่
  ลองใหม่ได้ และใครเป็นผู้บันทึกเมื่อลองใหม่
- ตัวประมวลผลสองตัว (API สองเครื่อง หรือรอบตามเวลากับรอบที่คนสั่ง) ต้องไม่ตัดยอดขายเดียวสองครั้ง

Product owner ตัดสินแต่ละข้อไว้ใน #17 เอกสารนี้บันทึกไว้

## การตัดสินใจ

1. **เอกสารการใช้วัตถุดิบหนึ่งใบต่อหนึ่ง sales event** เลขที่มาจากลำดับ `BC` บันทึก event สาขา เมนู
   สูตรที่ใช้ในวันขาย และหนึ่งบรรทัดต่อวัตถุดิบ พร้อมปริมาณตามทฤษฎีแบบตรงตัวและปริมาณที่ลงบัญชีซึ่งปัด
   ครั้งเดียว (ADR-0019) `sales_event_id` ห้ามซ้ำ จึงมีเอกสารใบเดียวต่อ event ไม่ว่าจะทำงานพร้อมกันแค่ไหน
   บัญชีสต๊อกไม่ยอมลงเอกสารใบเดิมสองครั้ง และตัวประมวลผลจองยอดขายด้วย `FOR UPDATE SKIP LOCKED`
   ก่อนเขียนอะไร
2. **เวลาทางธุรกิจของทุกรายการคือเวลาขาย** เฉพาะเอกสารประเภทนี้ วันทางธุรกิจคือวันที่ขายตามเขตเวลาของ
   บริษัท (ADR-0018) ส่วนเวลาที่ลงบัญชีคือเวลาที่ประมวลผล POS ที่ออฟไลน์ไปหนึ่งวันจึงแสดงการใช้วัตถุดิบที่
   ช้าไปหนึ่งวัน ตามที่ ADR-0002 ยอมรับไว้
3. **การตัดที่สาขา** ใช้ FEFO จาก lot ที่ใช้ได้ของสาขาก่อน ส่วนที่ไม่พอจะตัดจาก lot ของสินค้านั้นที่สาขา
   รับเข้ามาล่าสุด แม้ lot นั้นหมดแล้วหรือหมดอายุแล้ว lot นั้นจะติดลบ และหน้าสต๊อกจะขอให้นับ (#8) ถ้า lot
   นั้นหมดอายุแล้วในวันขาย เอกสารและรายงานการใช้จะแสดงว่า **ตัดจาก lot ที่หมดอายุ** เป็นสัญญาณด้านความ
   ปลอดภัยของอาหารที่ไม่ซ่อน
4. **lot แทน (placeholder lot)** ใช้เมื่อสาขาไม่เคยมีสินค้านั้น หนึ่ง lot ต่อสาขาและสินค้า เลขที่
   `PH-<สาขา>-<สินค้า>` สร้างครั้งแรกเมื่อต้องใช้ ไม่มีของอยู่ จึงมีแต่ติดลบ ไม่มีวันหมดอายุ FEFO ไม่หยิบ
   และเอกสารประเภทอื่นแตะไม่ได้ ต้นทุนคือต้นทุนของ lot ของสินค้านั้นที่รับเข้ามาล่าสุดที่ใดก็ได้ในเครือ
   ติดป้าย **ต้นทุนประมาณ** ถ้าเครือไม่เคยมีสินค้านั้น ต้นทุนเป็น 0 ติดป้าย **ไม่รู้ต้นทุน** ต้นทุนคงที่ตั้งแต่
   สร้าง เหมือน lot อื่น การเรียกคืนสินค้า (#23) ต้องไม่รายงาน lot แทนเป็น lot ต้นทาง เพราะไม่ใช่ lot ที่มี
   ใครรับเข้ามา
5. **ยอดขายที่ลงเวลาล้ำหน้าเกินไปถูกพักไว้ ไม่ใช่ไม่สำเร็จ** เมื่อเวลาขายช้ากว่าเวลาที่ ERP ได้รับเกินค่าที่
   บริษัทตั้งไว้ (เป็นการตั้งค่า ค่าเริ่มต้น 10 นาที ADR-0007) ยอดขายจะยังเป็นสถานะได้รับ ติดธง
   `sale_time_ahead` แสดงบนหน้าจอ และบันทึก log ครั้งเดียว ไม่แก้เวลาของยอดขาย คนประมวลผลใหม่ได้เมื่อถึง
   วันขาย ยอดขายที่ลงวันหลังวันนี้แต่อยู่ในค่าที่ตั้ง (ขายก่อนเที่ยงคืนเล็กน้อยบนนาฬิกาที่เร็วไปนิด) แค่รอถึงวัน
6. **ยอดขายที่เป็นการใช้วัตถุดิบไม่ได้จะไม่สำเร็จพร้อมเหตุผล** ได้แก่ `unknown_menu_item`,
   `unknown_modifier`, `no_recipe_in_effect`, `sold_by_mismatch`, `inactive_ingredient` หรือ
   `negative_usage` เมนูหรือตัวเลือกเสริมที่เลิกขายแล้วยังตัดวัตถุดิบตามสูตร เพราะการขายเกิดขึ้นแล้ว
7. **การประมวลผลใหม่** คนที่มีสิทธิ์ `sales_event:reprocess` (ผู้ดูแลระบบ) สั่งให้ลองยอดขายที่ไม่สำเร็จหรือถูก
   พักอีกครั้ง และครั้งนั้นเป็นของคนนั้น คนนั้นเป็นผู้บันทึกการใช้วัตถุดิบที่ตามมา และผลเหมือนสำเร็จตั้งแต่ครั้ง
   แรก เปิดให้เฉพาะเมื่อช่วยได้: เมนูหรือตัวเลือกเสริมที่ไม่รู้จักและวัตถุดิบที่เลิกใช้ได้เสมอ ยอดขายที่ถูกพักได้
   เมื่อถึงวันขาย ไม่มีสูตรในวันขายได้เฉพาะในวันขายนั้นเอง เพราะสูตรเริ่มย้อนหลังไม่ได้ ยอดขายของวันที่ผ่านไป
   แล้วจึงค้างเป็นไม่สำเร็จ (#76) และไม่เปิดสำหรับวิธีขายที่ไม่ตรงหรือสูตรที่ขัดกัน ทุกครั้งที่ลองและทุกคำสั่ง
   เก็บไว้ตามลำดับ และไม่มีวันแก้
8. **บัญชีอัตโนมัติ** "PaynEat ERP — automatic" เป็นผู้บันทึกสิ่งที่ตัวประมวลผลทำเอง ไม่มีรหัสผ่านที่ใช้ได้
   ไม่มีการยืนยันตัวตนขั้นที่สอง ไม่มีบทบาท ไม่เคยล็อกอิน และไม่อนุมัติอะไร ฐานข้อมูลปฏิเสธทุกข้อนี้ ไม่แสดงใน
   รายชื่อผู้ใช้ แต่แสดงชื่อในทุกเอกสารและบันทึกตรวจสอบที่บัญชีนี้บันทึก ใช้บันทึกการใช้วัตถุดิบที่สาขาเท่านั้น
9. **ตัวประมวลผล** ทำงานเป็นรอบ (การตั้งค่า 0 คือปิด) ผ่าน job lock ที่ดัดแปลงจาก Cwork ให้ทำงานทีละเครื่อง
   และคนสั่งรันทันทีได้ ความถูกต้องไม่ได้พึ่ง lock นี้ ข้อ 1 ทำหน้าที่นั้น
10. **ยังไม่ตรวจงวดที่ปิดแล้ว** เมื่อ #25 เพิ่มการปิดงวด ยอดขายในงวดที่ปิดแล้วมีจุดตรวจจุดเดียว คือใน
    ตัวประมวลผลก่อนสร้างเอกสาร จนถึงตอนนั้น ยอดขายที่มาช้าลงบัญชีในวันของมันเอง ไม่ว่าวันไหน

## ผลที่ตามมา

- สต๊อกและต้นทุนยังมองเห็นได้เมื่อสาขาขายของที่ไม่มี ยอดติดลบอยู่บน lot จริงหรือ lot แทน ไม่ถูกกลืนหาย
  และค่าประมาณทุกค่าบอกว่าเป็นค่าประมาณ
- นาฬิกา POS ที่ผิดดันการใช้วัตถุดิบไปงวดที่ห่างไกลไม่ได้ ยอดขายจะรอคน
- แก้ข้อมูลหลักแล้วประมวลผลใหม่ ได้เอกสารเหมือนยอดขายที่ไม่เคยไม่สำเร็จ
- ยังปรับยอด lot แทนด้วยเอกสารปรับปรุงสต๊อกไม่ได้ เพราะเอกสารปรับปรุงใช้ได้เฉพาะ lot ที่ FEFO เห็น การนับ
  สาขาที่ขายของที่ไม่เคยรับเข้า ต้องรับสินค้าเข้าก่อน issue ถัดไปจะตัดสินว่าการนับจะเคลียร์ lot แทนอย่างไร

## ทางเลือกที่พิจารณา

- **ปฏิเสธหรือให้ยอดขายที่สาขาไม่มีของพอไม่สำเร็จ** ไม่เลือก ตาม ADR-0003 เพราะการขายเกิดขึ้นแล้ว
- **กระจายส่วนที่ขาดไปที่ lot หมดอายุของสาขาหรือของโรงงาน** ไม่เลือก เพราะจะอ้างว่าใช้ lot ที่สาขาอาจไม่เคย
  มี และสต๊อกโรงงานต้องไม่ติดลบ
- **แก้เวลาขายให้เท่ากับเวลาที่ได้รับ** ไม่เลือก เพราะ ERP จะสร้างข้อเท็จจริงขึ้นเอง การพักไว้ทำให้คนเห็นปัญหาแทน
- **ลงบัญชีในนามคนที่ลงทะเบียน POS** ไม่เลือก เพราะรายการจะระบุชื่อคนที่ไม่ได้ทำอะไร และคนนั้นอาจถูกปิด
  บัญชีหรือลาออก
