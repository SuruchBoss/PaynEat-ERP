# ADR-0027: ใบสั่งผลิต: วันที่ทางธุรกิจเดียวต่อใบ การเลือก lot แบบ FEFO และการแก้ไข การปันต้นทุนแบบไม่สูญหลัก และผังความสัมพันธ์ lot เมื่อกลับรายการ

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-10
- **English:** [0027-production-orders-picking-cost-rounding-and-genealogy.md](0027-production-orders-picking-cost-rounding-and-genealogy.md)

## บริบท

ADR-0004 กำหนดว่าใบสั่งผลิตแบ่งต้นทุนของ lot วัตถุดิบที่ใช้ไปให้ผลผลิตตามสัดส่วนปันต้นทุนใน BOM แล้วหารส่วนของแต่ละผลผลิตด้วยจำนวนจริง
ได้เป็นต้นทุนต่อหน่วยของ lot ผลผลิต ADR-0006 กำหนดว่าเลือกวัตถุดิบแบบ FEFO (หมดอายุก่อนออกก่อน) ห้ามใช้ lot ที่หมดอายุ
และ lot ผลผลิตทุก lot ต้องเชื่อมกลับไปยัง lot วัตถุดิบที่ใช้ ADR-0014 กำหนดว่าวันหมดอายุของ lot ผลผลิตต้องไม่เกินวันหมดอายุของ lot
วัตถุดิบที่เร็วที่สุด แต่พอสร้างใบสั่งผลิต (#13) ยังมีคำถามที่การตัดสินใจเหล่านั้นไม่ได้ตอบ:

- ต้นทุนต่อหน่วยของ lot เก็บละเอียด 6 ตำแหน่ง (`NUMERIC(18,6)`, ADR-0019) การหารส่วนของมูลค่าวัตถุดิบด้วยจำนวนผลผลิตแทบไม่เคยลงตัว
  เช่น 1,000 บาทหาร 22 ชิ้นได้ชิ้นละ 45.4545… ไม่ว่าจะปัดอย่างไร มูลค่า lot ผลผลิตรวมกันจะมากหรือน้อยกว่ามูลค่าวัตถุดิบที่ใช้ไปนิดหน่อย
  issue #13 ขอว่าผลรวมมูลค่า lot ผลผลิตต้องเท่ากับมูลค่าวัตถุดิบที่ใช้ไปพอดี ซึ่งเป็นไปไม่ได้ทุกใบเมื่อต้นทุนต่อหน่วยมี 6 ตำแหน่ง
- การตัดวัตถุดิบและการผลิตของใบหนึ่งเกิดในวันไหน และ lot หมดอายุหรือไม่ดูเทียบกับวันไหน
- หัวหน้าไลน์ผลิตแก้ lot ที่ FEFO เลือกให้ได้แค่ไหน
- อัตราผลได้ของผลผลิตที่นับเป็นชิ้นวัดอย่างไร
- ใบสั่งผลิตที่ post แล้วแก้ได้ด้วยการกลับรายการ (#7) เท่านั้น แล้วผังความสัมพันธ์ lot ของใบนั้นจะเป็นอย่างไร

## การตัดสินใจ

1. **ใบสั่งผลิตหนึ่งใบมีวันที่ทางธุรกิจเดียว** ใบสั่งผลิตเปิดในวันที่ทางธุรกิจหนึ่ง (ค่าตั้งต้นคือวันนี้ ห้ามเป็นวันในอนาคต)
   ทุกอย่างของใบตัดสินด้วยวันนั้น: เวอร์ชัน BOM ที่มีผล (ใบบันทึกไว้) lot ไหนหมดอายุแล้ว วันที่ลงการตัดวัตถุดิบและ lot ผลผลิต
   และวันหมดอายุของ lot ผลผลิต
2. **แผนคำนวณจาก BOM** ใบระบุว่าจะใช้วัตถุดิบตัวแรกของ BOM เท่าไร ("ไก่ทั้งตัว 500 กก.") แล้วทุกบรรทัดของ BOM ถูกปรับตามสัดส่วนนั้น
   ปัดครึ่งขึ้นตามจำนวนตำแหน่งทศนิยมของสินค้า ผลผลิตตามแผนคือผลได้ที่คาดไว้ใน BOM ตามสัดส่วนนั้น เป็นแผนที่แสดงว่าเป็นแผน ไม่ถูก post
3. **เลือก lot ตอนปล่อยใบ และหัวหน้าไลน์แก้ได้** การปล่อยใบจากร่างจะล็อกเวอร์ชัน BOM โรงงาน และแผน แล้วเลือก lot ของวัตถุดิบแต่ละตัว
   แบบ FEFO จากสต็อกของโรงงานในวันที่ของใบ (วันหมดอายุก่อน แล้วตามเลข lot) ส่วนที่ FEFO ครอบไม่ได้จะแสดงว่าขาดอยู่
   หลังจากนั้นหัวหน้าไลน์เลือก lot อื่นหรือจำนวนอื่นได้ แต่ห้ามเลือก lot ที่หมดอายุแล้วในวันที่ของใบ และใบจะบันทึกว่ามีการแก้ lot
   ส่วนโรงงานยังมีของพอหรือไม่ ตัดสินตอน post เท่านั้น ภายใต้การล็อกยอดคงเหลือ (ADR-0003): สต็อกโรงงานไม่มีวันติดลบ
4. **อัตราผลได้วัดด้วยน้ำหนักจริง ไม่ประมาณ** เหมือน ADR-0026 บรรทัด kg หรือ g หนักเท่าปริมาณ บรรทัดที่นับด้วยหน่วยอื่นต้องบันทึก
   น้ำหนักที่ชั่งจริง ถ้าไม่มี ใบจะไม่แสดงอัตราผลได้จริงและ post ไม่ได้ ผลผลิตที่น้ำหนักไม่คงที่ (variable-weight) ต้องบันทึก
   จำนวนชิ้นด้วยนอกจากน้ำหนัก (ADR-0005)
5. **การปันต้นทุนเก็บครบทุกหลัก และปัดเพียงจุดเดียว** สำหรับผลผลิตแต่ละรายการ:
   - **มูลค่าที่ปันให้** = มูลค่าวัตถุดิบที่ใช้ไป × สัดส่วน ÷ 100 เก็บแบบไม่ปัดใน `NUMERIC` ที่ไม่จำกัดหลัก เพราะสัดส่วนรวมได้ 100.00 พอดี
     (ADR-0026) มูลค่าที่ปันให้ทุกรายการจึงรวมได้มูลค่าวัตถุดิบพอดีถึงหลักสุดท้าย
   - **ต้นทุนต่อหน่วยของ lot** = มูลค่าที่ปันให้ ÷ จำนวนจริง ปัดครึ่งขึ้นที่ 6 ตำแหน่ง นี่คือการปัดจุดเดียว และเมื่อ lot นี้ถูกใช้ต่อ
     การใช้ก็ยังใช้ต้นทุนนี้ตาม ADR-0004
   - **ส่วนต่างจากการปัดเศษ** = มูลค่าที่ปันให้ ลบ มูลค่า lot (จำนวน × ต้นทุนต่อหน่วย) เก็บแบบไม่ปัดที่บรรทัดผลผลิตของใบ และแสดงบนใบ

   ดังนั้นทุกใบที่ post แล้ว **Σ มูลค่า lot ผลผลิต + Σ ส่วนต่างจากการปัดเศษ = มูลค่าวัตถุดิบที่ใช้ไป พอดี**
   และส่วนต่างของแต่ละผลผลิตไม่เกินจำนวนของมัน × 0.0000005 นี่คือกฎที่ issue #13 ขอ ("เศษจากการปัดต้องมีกฎที่เขียนไว้")
   และต่างจากถ้อยคำตามตัวอักษร "ผลรวมมูลค่า lot ผลผลิตเท่ากับมูลค่าวัตถุดิบที่ใช้ไปพอดี": มูลค่าที่การปัดขยับไม่ได้ใส่ไว้ใน lot ไหน
   แต่บันทึกไว้ข้าง lot
6. **ผลผลิตที่จำนวนจริงเป็นศูนย์ทำให้ใบถูกปฏิเสธ** ผลผลิตนั้นรับต้นทุนไม่ได้ ใบจึงถูกปฏิเสธ (`zero_output_quantity`) แทนที่จะหารด้วยศูนย์
   หรือย้ายส่วนของมันไปให้ผลผลิตอื่น ผลผลิตที่ไม่ได้อะไรออกมาจริงๆ แปลว่าใบไม่ได้ทำตาม BOM: ให้ยกเลิกใบ หรือแก้ BOM
7. **post ครั้งเดียว ในธุรกรรมเดียว** โมดูล ledger ตัด lot ที่เลือก สร้าง lot หนึ่ง lot ต่อผลผลิตหนึ่งรายการ และเขียนผังความสัมพันธ์ lot
   ทั้งหมดในธุรกรรมเดียว หรือไม่เขียนอะไรเลย บรรทัดของใบนับวัตถุดิบก่อนแล้วจึงเป็นผลผลิต เลข lot ผลผลิตจึงต่อจากวัตถุดิบ
   (MO-2026-00001/2 คือผลผลิตรายการแรกของ BOM ที่มีวัตถุดิบตัวเดียว)
8. **ผังความสัมพันธ์ lot บันทึกเฉพาะสิ่งที่วัดได้** lot ผลผลิตแต่ละ lot เชื่อมกับ lot วัตถุดิบทุก lot ที่ใบใช้ไป พร้อมจำนวนที่ใบใช้จาก lot
   วัตถุดิบนั้นทั้งหมด ERP ไม่แบ่งจำนวนนี้ให้แต่ละผลผลิต เพราะไม่มีใครรู้ว่าน่องชิ้นไหนมาจากไก่ตัวไหน จำนวนที่แบ่งเองจะเป็นค่าประมาณ
   ที่แสดงเหมือนข้อเท็จจริง
9. **การกลับรายการเก็บผังความสัมพันธ์ไว้เป็นประวัติ แต่เอาออกจากการย้อนรอย** ผังความสัมพันธ์ lot เขียนเพิ่มได้อย่างเดียว เมื่อใบถูกกลับรายการ
   ลิงก์ของใบยังอยู่ พร้อมป้ายว่าเป็นของใบที่ถูกกลับรายการแล้ว การย้อนรอยจะตามเฉพาะลิงก์ของใบที่ยังมีผล และการกลับรายการถูกปฏิเสธ
   เหมือนเอกสารอื่นเมื่อ lot ผลผลิตถูกเคลื่อนไปแล้ว (เพราะจะทำให้โรงงานติดลบ)
10. **อัตราผลได้ที่แย่ต้องมองเห็น** ใบที่ post แล้วบันทึกอัตราผลได้จริงและที่คาดไว้ และใบล่าสุดที่ยังมีผลของแต่ละ BOM แสดงผ่าน metric
    `erp_production_yield_percent`

## ผลที่ตามมา

- มูลค่า lot ยังถูกต้องที่ 6 ตำแหน่ง ซึ่งเป็นความละเอียดที่เอกสารและรายงานอื่นใช้อยู่แล้ว และใบอธิบายได้ถึงหลักสุดท้ายว่ามูลค่าวัตถุดิบไปอยู่ไหน
- มูลค่า lot ผลผลิตไม่เท่ากับมูลค่าที่ปันให้พอดี ต่างกันได้ไม่เกินครึ่งในล้านบาทต่อหน่วย และบันทึกไว้บนใบ รายงานที่ต้องใช้มูลค่าที่ปันให้อ่านจากใบ
- หัวหน้าไลน์บันทึกสิ่งที่หน้างานทำจริงได้ (lot อื่นอยู่ใกล้กว่า lot หนึ่งมีไม่พอ) โดย ERP ไม่แสร้งว่าทำตาม FEFO และไม่ใช้ lot หมดอายุเลย
- ผลผลิตที่นับเป็นชิ้นต้องมีตาชั่งที่โรงงานจึงจะ post ได้

## ทางเลือกที่พิจารณา

- **เพิ่มทศนิยมของต้นทุนต่อหน่วย** (เช่น 12 ตำแหน่ง) ส่วนต่างน้อยลงแต่ไม่หายไป หนึ่งในสามบาทก็ยังไม่มีทศนิยมที่ลงตัว
  และทุก lot ทุกรายการบัญชี ทุกรายงานต้องเปลี่ยน โดยไม่ได้ความแม่นยำพอดีเพิ่มขึ้น
- **เก็บมูลค่าไว้ที่ lot แทนต้นทุนต่อหน่วย** แม่นพอดี แต่การใช้ lot ต้องหารมูลค่าด้วยจำนวนที่ใช้ ซึ่งขัดกับ ADR-0004
  ที่ว่า "การใช้ต้องใช้ต้นทุนของ lot ที่ใช้" และย้ายการปัดเศษเดียวกันไปไว้ทุกครั้งที่ใช้
- **ใส่เศษทั้งหมดไว้ใน lot ผลผลิตตัวสุดท้าย** รวมได้พอดีก็ต่อเมื่อให้ lot หนึ่งมีต้นทุนต่อหน่วยที่ไม่ใช่ส่วนของมัน ÷ จำนวนของมัน
  และก็ยังทำไม่ได้เมื่อเศษหารด้วยจำนวนของ lot นั้นไม่ลงตัว
- **แบ่งจำนวนในผังความสัมพันธ์ให้แต่ละผลผลิตตามสัดส่วนหรือน้ำหนัก** ไม่เลือก เพราะเป็นค่าประมาณที่แสดงเหมือนค่าที่วัดได้
