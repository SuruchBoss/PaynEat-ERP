# ADR-0017: การตรวจนับสต๊อก: นับแบบไม่เห็นยอด ณ เวลาตรวจนับ และที่สาขาปันส่วนต่างลง lot ตามกฎ

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-26
- **English:** [0017-stock-counts.md](0017-stock-counts.md)

## บริบท

การตรวจนับคือจุดที่ตัวเลขในระบบมาเจอของบนชั้นจริง ADR-0003 ยอมให้สต๊อกสาขาติดลบ แล้วขอให้ตรวจนับเมื่อติดลบ ส่วน
ADR-0008 กำหนดให้ใบปรับยอดจากการตรวจนับต้องมีคนอื่นอนุมัติ ยังเหลือสามคำถามที่ต้องตอบ และแต่ละข้อมีคำตอบผิดที่ฟังดูมี
เหตุผล:

- **"ยอดตามระบบ" คือยอด ณ เวลาไหน** ระหว่างที่สาขานับ การขายยังเกิดขึ้นเรื่อยๆ และ POS ที่ออฟไลน์อยู่จะส่งยอดขายมาช้า
  ไปหลายชั่วโมง (ADR-0002) ถ้าเทียบยอดนับกับ "ยอดคงเหลือตอนนี้" ก็เท่ากับเทียบสองช่วงเวลาที่ต่างกัน
- **สาขานับอะไร** โรงงานติดป้าย lot ไว้ แต่สาขาไม่ได้ติด POS ไม่รู้จัก lot และคนครัวหยิบถุงที่อยู่ใกล้มือที่สุด (ADR-0006)
  การให้พนักงานสาขานับแยกราย lot จะได้ตัวเลขที่ดูละเอียดแต่ไม่จริง
- **ส่วนต่างที่สาขาลงที่ lot ไหน** บัญชีสต๊อกเก็บเป็นราย lot (ADR-0003) ส่วนต่างระดับรายการสินค้าจึงต้องถูกลงที่ lot
  สักทาง และกฎที่ใช้เป็นตัวกำหนดว่าส่วนต่างนั้นมีต้นทุนเท่าไร

## การตัดสินใจ

1. **ใบตรวจนับมีเวลาตรวจนับ** เอกสารหนึ่งใบใช้กับสถานที่เดียว **ยอดตามระบบ**ของแต่ละบรรทัดคือยอดคงเหลือ **ณ เวลา
   ตรวจนับ** ตามเวลาที่เกิดรายการ (ADR-0018) งานไม่ต้องหยุด รายการที่ post เข้ามาระหว่างและหลังการนับไม่เปลี่ยนยอดที่ใช้
   เทียบ
2. **นับแบบไม่เห็นยอดในระบบ** คนนับกรอกจำนวนโดยไม่เห็นยอดตามระบบ ยอดตามระบบและส่วนต่างจะแสดงหลังส่งใบตรวจนับแล้ว
   คนนับที่เห็นตัวเลขที่ควรจะเป็นมักจะนับได้ตัวเลขนั้น
3. **โรงงานและคลังนับราย lot ส่วนสาขานับรายสินค้า** บรรทัดของโรงงานหรือคลังระบุ lot บรรทัดของสาขาระบุรายการสินค้า
   ในหน่วยหลัก พร้อมจำนวนหน่วยที่สองสำหรับรายการน้ำหนักแปรผัน (ADR-0005) หน้าจอตรวจนับที่สาขาไม่ถาม lot เลย
4. **ส่วนต่างที่สาขาถูกปันลง lot ด้วยกฎตายตัว** ซึ่งเขียนเป็น pure domain function:
   - **ของขาด** (นับได้น้อยกว่ายอดตามระบบ) ตัดจาก lot ของรายการนั้นที่สาขาซึ่งมียอดเป็นบวก เรียงวันหมดอายุเร็วสุดก่อน
     รวม lot ที่หมดอายุแล้วด้วย เพราะการตรวจนับบันทึกว่าของอะไรหายไป ไม่ใช่ว่าของอะไรเบิกได้ ถ้าขาดมากกว่ายอดบวก
     ทั้งหมด ส่วนที่เหลือลงที่ **lot ที่สาขารับเข้ามาล่าสุด** ของรายการนั้น ซึ่งเป็นกฎเดียวกับที่การใช้วัตถุดิบของสาขาใช้
     เมื่อของหมด (#17)
   - **ของเกิน** (นับได้มากกว่ายอดตามระบบ) ใช้ปรับ lot ที่**ติดลบ**ของรายการนั้นให้กลับเป็นศูนย์ก่อน เรียงวันหมดอายุ
     เร็วสุดก่อน ส่วนที่เหลือลงที่ lot ที่สาขารับเข้ามาล่าสุด
   - **ของเกินที่ไม่มี lot ให้ลง** (สาขาไม่เคยรับรายการนี้เลย) บรรทัดนั้นถูกปฏิเสธ พร้อมบอกเหตุผล lot เกิดได้จากการรับ
     สินค้าและการผลิตเท่านั้น (ADR-0006) ของที่พบที่สาขาทั้งที่ ERP ไม่เคยส่งไป จึงชี้ว่ามีใบโอนที่ขาดหายไป และการ
     ตรวจนับไม่มีสิทธิ์สร้างมันขึ้นมาเอง
   - ทุกรายการที่ปันลงไปใช้ต้นทุนของ lot นั้น (ADR-0004) ส่วนต่างจึงมีมูลค่าเสมอ

   ตัวอย่างคำนวณ: สาขา B-01 น่องไก่ เวลาตรวจนับ 22:00 ยอดตามระบบ 40 ชิ้น อยู่ในสาม lot

   | Lot | วันหมดอายุ | ยอด ณ 22:00 |
   |---|---|---|
   | L1 | 1 ต.ค. | 5 |
   | L2 | 2 ต.ค. | 20 |
   | L3 | 3 ต.ค. (รับเข้าล่าสุด) | 15 |

   นับได้ 28 (ขาด 12): L1 −5, L2 −7 · นับได้ 45 (เกิน 5): ไม่มี lot ติดลบ จึงลง L3 +5
   ถ้า L1 เป็น −3, L2 เป็น 43 และ L3 เป็น 0 (ยอดรวมยังเป็น 40) นับได้ 45 จะได้ L1 +3 แล้ว L3 +2
5. **บรรทัดของโรงงานหรือคลังที่ระบุ lot ซึ่งไม่มีในระบบจะถูกปฏิเสธ** การตรวจนับสร้าง lot ที่นั่นไม่ได้เช่นกัน
6. **ใบตรวจนับ post เป็นใบปรับยอด และต้องมีคนอื่นอนุมัติ** ใช้เอกสารปรับยอดและกฎการอนุมัติของ ADR-0008 (ไม่มีใคร
   อนุมัติใบตรวจนับที่ตัวเองสร้าง) ตอนอนุมัติ ระบบคำนวณยอดตามระบบใหม่ ณ เวลาตรวจนับเดิม ถ้ามีรายการที่ post เข้ามาระหว่างนั้น
   โดยมีเวลาที่เกิดรายการก่อนเวลาตรวจนับ ยอดจะสะท้อนรายการนั้น และผู้อนุมัติจะเห็นว่าส่วนต่างเปลี่ยนไป
7. **ยอดขาย POS ที่มาช้าแสดงให้ผู้อนุมัติเห็น แต่ไม่ต้องรอ** ที่สาขา หน้าจออนุมัติแสดงเวลาขายล่าสุดที่ ERP ได้รับจาก
   POS instance แต่ละเครื่องที่ให้บริการสาขานั้น ถ้าเครื่องใดยังส่งมาไม่ถึงเวลาตรวจนับ จะเตือนว่ายอดขายก่อนการนับอาจยัง
   มาไม่ถึง ผู้อนุมัติยัง post ได้ และระบบบันทึกว่ารับทราบคำเตือนแล้ว ยอดขายที่มาถึงทีหลังจะ post เป็นการใช้วัตถุดิบตามปกติ
   (ADR-0003) และส่วนต่างที่เกิดจากยอดขายนั้นจะถูกพบในการตรวจนับครั้งถัดไป

## ผลที่ตามมา

- ยอดตรวจนับเทียบกับระบบได้จริง แม้สาขาไม่เคยปิดร้าน
- ต้นทุนของส่วนต่างที่สาขาถูกกำหนดด้วยกฎที่ใครก็คำนวณตามด้วยมือได้ ไม่ได้ขึ้นกับว่าฟังก์ชันบังเอิญหยิบ lot ไหน
- การตรวจนับที่สาขายังเป็นระดับรายการสินค้า มีข้อจำกัดเดียวกับ ADR-0006 คือถ้าวันหนึ่งสาขาเลือก lot ตอนเปิดแพ็ก ก็จะนับ
  ราย lot ได้ และจะทบทวนกฎนี้ใหม่
- ใบตรวจนับที่ post ก่อน POS ออฟไลน์ส่งยอดขายมาครบ จะทิ้งส่วนต่างไว้ให้การนับครั้งถัดไปพบ คำเตือนทำให้เรื่องนี้มองเห็นได้
  ส่วนการบล็อกการนับจนกว่า POS ทุกเครื่องจะส่งยอดมา จะทำให้แท็บเล็ตที่ออฟไลน์เครื่องเดียวขวางไม่ให้สาขาปิดบัญชีได้เลย

## ทางเลือกที่พิจารณาแล้ว

- **เทียบกับยอดคงเหลือตอนส่งใบตรวจนับ** ไม่เลือก: ยอดขายระหว่างนับทำให้ทุกใบคลาดเท่ากับของที่ขายไประหว่างนับ
- **หยุดความเคลื่อนไหวของสถานที่ระหว่างนับ** ไม่เลือก: ร้านอาหารหยุดขายเพื่อนับของไม่ได้
- **ให้สาขานับราย lot** ไม่เลือกใน v1: พนักงานสาขาแยก lot ไม่ออก ตัวเลขที่ได้จึงเป็นตัวเลขที่แต่งขึ้น
- **ลงส่วนต่างทั้งหมดของสาขาที่ lot เดียว** ไม่เลือก: ทำให้ส่วนต่างมีต้นทุนแบบสุ่ม และอาจทำให้ lot เดียวติดลบมาก
  ขณะที่ lot อื่นค้างยอดเก่าไว้
- **ปฏิเสธใบตรวจนับของสาขาจนกว่า POS ทุกเครื่องจะส่งยอดขายเลยเวลาตรวจนับ** ไม่เลือก: ดูหัวข้อผลที่ตามมา
