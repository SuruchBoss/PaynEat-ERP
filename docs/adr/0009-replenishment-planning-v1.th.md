# ADR-0009: การวางแผนเติมสต๊อกใน v1 — จุดสั่งซื้อ ใบขอเบิก MRP-lite

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-25
- **English:** [0009-replenishment-planning-v1.md](0009-replenishment-planning-v1.md)

## บริบท

เครือร้านอาหารจะได้หรือเสียกำไร (margin) จากการซื้อในปริมาณที่ถูกต้องในเวลาที่ถูกต้อง และผลิตเฉพาะสิ่งที่สาขาจะขาย
ได้ การพยากรณ์ความต้องการและการกำหนดจังหวะการซื้อตามราคาต้องอาศัยประวัติการขายที่ระบบยังไม่มีในวันแรก การพยากรณ์
ที่สร้างขึ้นโดยไม่มีประวัตินั้นก็คือตัวเลขที่แต่งขึ้น ซึ่งขัดกับเป้าหมายใน ADR-0001

## การตัดสินใจ

1. **จุดสั่งซื้อ** ที่โรงงานและคลังจะแจ้งเตือนรายการสินค้าที่ควรสั่งซื้อจากซัพพลายเออร์
2. **สาขาเป็นผู้ออกใบขอเบิก** แต่ละรายการสินค้ามีระดับสต๊อกมาตรฐานแยกต่อสาขา หน้าจอใบขอเบิกจะแนะนำจำนวนเท่ากับ
   ระดับสต๊อกมาตรฐาน ลบยอดคงเหลือปัจจุบัน ลบสต๊อกที่อยู่ระหว่างขนส่งแล้ว จากนั้นผู้จัดการสาขาแก้ไขและส่ง ใน v1 โรงงาน
   จะไม่ผลักสต๊อกไปยังสาขาโดยอัตโนมัติ
3. **MRP-lite รวมใบขอเบิกที่ยังเปิดอยู่** เป็นใบสั่งผลิตที่แนะนำ (โดยใช้สูตรการผลิตและอัตราผลได้ที่คาดไว้) และใบสั่งซื้อ
   ที่แนะนำ (สำหรับวัตถุดิบนำเข้าที่ยังขาดหลังพิจารณาจุดสั่งซื้อแล้ว) **เป็นเพียงคำแนะนำเท่านั้น:** คนเป็นผู้ตรวจทานและ
   สร้างเอกสารจริง
4. **การพยากรณ์และการกำหนดจังหวะการซื้อเป็นงานในอนาคต** ของ AI agent ที่วิเคราะห์ประวัติการขายและการซื้อแล้วส่ง
   การแจ้งเตือน agent นี้จะอ่านบัญชีเคลื่อนไหวและเอกสารชุดเดียวกัน ไม่มีสิ่งใดใน v1 ที่ออกแบบโดยอิงกับ agent นี้ นอกจาก
   การเก็บประวัตินั้นให้ครบถ้วน

## ผลที่ตามมา

- โรงงานตอบได้ว่า "พรุ่งนี้จะผลิตอะไรและซื้ออะไร" จากคำขอจริงของสาขา ไม่ใช่จากการเดา
- คุณภาพการวางแผนขึ้นอยู่กับการดูแลระดับสต๊อกมาตรฐานให้เป็นปัจจุบัน ERP แสดงว่าพลาดระดับสต๊อกมาตรฐานบ่อยแค่ไหน
  ระดับสต๊อกมาตรฐานที่ตั้งไว้ไม่ดีจึงมองเห็นได้

## ทางเลือกที่พิจารณา

- **การเติมสต๊อกอัตโนมัติโดยให้โรงงานผลักไปยังสาขา** เลื่อนออกไป: ต้องมีระดับสต๊อกมาตรฐานและข้อมูลการใช้ที่เชื่อถือได้
  ก่อน
- **การพยากรณ์เชิงสถิติใน v1** ปฏิเสธ: ยังไม่มีประวัติ และการพยากรณ์ที่แต่งขึ้นจะบั่นทอนความเชื่อถือต่อตัวเลขอื่นทุกตัว
