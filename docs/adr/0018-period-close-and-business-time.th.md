# ADR-0018: ปิดงวดตามวันที่เกิดรายการ และยอดขายที่มาถึงหลังงวดปิดไปแล้ว

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-26
- **English:** [0018-period-close-and-business-time.md](0018-period-close-and-business-time.md)

## บริบท

ADR-0003 ข้อ 7 ปิดงวดรายสถานที่ด้วยวันที่ปิดงวดถึง และให้การเปิดงวดใหม่เป็นงานของ admin ที่มีบันทึกการตรวจสอบ แต่ยังไม่ได้
บอกว่ารายการที่ post จะถูกตัดสินด้วยวันที่ไหน และยังมีจุดที่ขัดกับกฎอื่นอีกสองข้อ:

- POS ส่งยอดขายมาช้าได้หนึ่งวัน (ADR-0002) และ**ห้ามปฏิเสธการขายเพราะสต๊อก** (ADR-0003) ยอดขายที่มาช้าในวันที่ปิด
  งวดไปแล้วก็ปฏิเสธไม่ได้เช่นกัน เพราะการปฏิเสธจะทำให้การใช้วัตถุดิบจริงหายไปจากระบบ
- การใช้วัตถุดิบของสาขาแยกเวลาที่ขายออกจากเวลาที่ post อยู่แล้ว (#17) การตรวจนับ (ADR-0017) และยอดคงเหลือ "ณ วันที่"
  ก็ต้องแยกแบบเดียวกันทุกที่ ไม่อย่างนั้นคำว่า "ณ วันที่" จะมีความหมายต่างกันไปในแต่ละรายงาน

ฝ่ายการเงินยังต้องมั่นใจว่าตัวเลขที่นำเข้าโปรแกรมบัญชีไปแล้วไม่ถูกเปลี่ยนโดยไม่รู้ตัว และถ้าเปลี่ยน ต้องมีการบอกอย่างชัดเจน

## การตัดสินใจ

1. **ทุกรายการเคลื่อนไหวมีเวลาที่เกิดรายการและเวลาที่ post** เวลาที่เกิดรายการคือเวลาที่ความเคลื่อนไหวเกิดขึ้นจริง เช่น
   วันที่รับสินค้า ผลิต หรือส่งของตามเอกสาร หรือเวลาขายของ event ยอดขาย ส่วนเวลาที่ post คือเวลาที่ ERP บันทึกรายการ
   วันที่ของเอกสารตั้งต้นเป็นวันนี้ และย้อนหลังได้ แต่ห้ามเป็นวันในอนาคต ยอดคงเหลือ ณ วันที่ การตรวจนับ และตัวเลขรายงวด
   ใช้**เวลาที่เกิดรายการ**ทั้งหมด
2. **การปิดงวดคือวันที่ปิดงวดถึงของแต่ละสถานที่ ตามเขตเวลาของบริษัท** เขตเวลาเป็นค่าตั้งค่า (ค่าเริ่มต้น `Asia/Bangkok`)
   การ post ที่จะเขียนรายการใดๆ ลงสถานที่หนึ่งด้วยวันที่เกิดรายการตรงกับหรือก่อนวันที่ปิดงวดถึงของสถานที่นั้น จะถูกปฏิเสธ
   ด้วยกฎ `period_closed` เอกสารที่เกี่ยวกับหลายสถานที่ (ใบโอน การส่งคืน) ตรวจทุกสถานที่ ส่วนสถานที่ระหว่างขนส่งใช้วันที่
   ปิดงวดถึงของสถานที่ต้นสังกัด
3. **การปิดงวดเดินหน้าได้อย่างเดียว** และปิดได้ไม่เกินเมื่อวาน ก่อนปิด console จะแสดงเอกสารร่างและเอกสารที่ส่งแล้วแต่
   ยังไม่ post ที่ลงวันที่อยู่ในงวดนั้น เอกสารเหล่านี้ไม่ขวางการปิดงวด แต่เมื่อปิดแล้ว จะ post ได้ด้วยวันที่หลังจากนั้นเท่านั้น
4. **ใครปิด ใครเปิดงวดใหม่** `admin` และ `finance` ปิดงวดได้ **เปิดงวดใหม่ได้เฉพาะ `admin`** โดยเลื่อนวันที่ย้อนกลับ
   และต้องระบุเหตุผล การเปิดงวดใหม่ถูกบันทึกว่าใคร เมื่อไร วันที่เดิมและวันที่ใหม่ และเหตุผล (ADR-0003, ADR-0008)
5. **ยอดขายจากงวดที่ปิดแล้วยัง post ได้** เมื่อเวลาขายของ event ยอดขายตรงกับหรือก่อนวันที่ปิดงวดถึงของสาขา การใช้
   วัตถุดิบจะ post ด้วยเวลาที่เกิดรายการเป็น**ต้นวันแรกที่ยังเปิดอยู่**ของสาขานั้น ติดเครื่องหมาย**มาช้าสำหรับงวดที่ปิดแล้ว**
   และเก็บเวลาขายเดิมไว้ ตัวเลขของงวดที่ปิดไม่เปลี่ยน งวดถัดไปแสดงการใช้วัตถุดิบนั้นพร้อมบอกว่ามาจากไหน เอกสารประเภท
   อื่นไม่ได้รับข้อยกเว้นนี้
6. **ไฟล์ export รายงวดมีฉบับแก้ไข** การ export ครอบคลุมช่วงวันที่ของสถานที่หนึ่งแห่งหรือหลายแห่ง และทำได้เฉพาะเมื่อทั้ง
   ช่วงปิดงวดแล้วทุกสถานที่ที่ครอบคลุม การเปิดงวดใหม่ในส่วนใดของช่วงที่ export ไปแล้ว จะทำให้ไฟล์ export นั้นถูกทำเครื่องหมาย
   ว่า**ถูกแทนที่** การ export ช่วงนั้นครั้งถัดไปเป็นฉบับแก้ไขใหม่ที่ระบุว่าแทนฉบับไหน ฝั่งบัญชีจึงแยกได้ว่าเป็นการแก้ไข
   ไม่ใช่ไฟล์ซ้ำ

## ผลที่ตามมา

- "สต๊อก ณ 30 กันยายน" มีความหมายเดียวกันในหน้ายอดคงเหลือ ใบตรวจนับ และไฟล์ export รายงวด
- งวดที่ปิดแล้วยังปิดอยู่ แม้ POS ที่ออฟไลน์จะทยอยส่งยอดมา ยอดขายที่มาช้าแสดงให้เห็นชัดในงวดที่รับเข้ามา
- การลงวันที่ย้อนหลังในงวดที่เปิดอยู่ทำได้และมองเห็นได้ เพราะทุกรายการเก็บทั้งสองเวลา
- บัญชีสต๊อก (#7) และการใช้วัตถุดิบของสาขา (#17) ต้องเก็บเวลาที่เกิดรายการตั้งแต่แรก ticket ที่ทำเสร็จก่อนและเก็บแค่เวลา
  ที่ post จะถูกขยายโดย ticket ปิดงวด ไม่ปล่อยให้ไม่สอดคล้องกัน
- แนวคิดเรื่องฉบับแก้ไขเป็นแบบเดียวกับข้อมูลค่าแรงของ Cwork โปรแกรมบัญชีจึงใช้กฎเดียวจัดการไฟล์ที่ถูกแทนที่จากทั้งสองระบบได้

## ทางเลือกที่พิจารณาแล้ว

- **ตัดสินการปิดงวดด้วยเวลาที่ post** ไม่เลือก: เอกสารที่คีย์วันที่ 2 ตุลาคมสำหรับของที่ส่งมาวันที่ 30 กันยายน จะไปอยู่
  ในเดือนตุลาคม และรายงาน "ณ วันที่" จะไม่ตรงกับของบนชั้น
- **ปฏิเสธยอดขายที่มาช้าในงวดที่ปิดแล้ว** ไม่เลือก: ขัดกับ ADR-0003 และทำให้การใช้วัตถุดิบหายไปเงียบๆ
- **เปิดงวดใหม่อัตโนมัติเมื่อยอดขายที่มาช้าเข้ามา** ไม่เลือก: ตัวเลขที่ export ไปแล้วจะเปลี่ยนโดยไม่มีใครตัดสินใจ
- **งวดรายเดือนเท่านั้น** ไม่เลือก: วันที่ปิดงวดถึงเรียบง่ายกว่า ให้เชนปิดรายสัปดาห์หรือรายวันก็ได้ และการ export
  เลือกช่วงวันที่เองได้
