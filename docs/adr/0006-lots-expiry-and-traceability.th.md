# ADR-0006: lot วันหมดอายุ และการย้อนรอยอย่างตรงไปตรงมา

- **สถานะ:** ยอมรับแล้ว; ชี้แจงข้อ 1 เมื่อ 2026-09-26 (ยอดยกมา, #7)
- **วันที่:** 2026-09-25
- **English:** [0006-lots-expiry-and-traceability.md](0006-lots-expiry-and-traceability.md)

## บริบท

เมื่อซัพพลายเออร์เรียกคืน (recall) สินค้าชุดการผลิต (batch) หนึ่ง เครือร้านอาหารต้องตอบสองคำถามให้ได้อย่างรวดเร็ว:
batch นั้นไปอยู่ที่ไหนบ้าง และอาจอยู่ในจานอาหารใดบ้าง โรงงานรู้ได้แน่ชัดว่าใช้ lot ใดไป แต่สาขามักรู้ไม่ได้: POS บันทึก
ว่า "ขายน่องไก่ไป 3 ชิ้น" ไม่ได้บันทึกว่าพ่อครัวเปิดถุงไหน และ POS ถูกออกแบบให้ไม่รับรู้เรื่อง lot โดยเจตนา เพื่อให้ยัง
ทำงานได้ด้วยตัวเอง (ADR-0002)

## การตัดสินใจ

1. **lot ถูกสร้างขึ้นจากใบรับสินค้าและผลผลิตจากการผลิตเท่านั้น** แต่ละ lot มีรายการสินค้า เอกสารต้นทาง ต้นทุนต่อหน่วย
   (ADR-0004) และวันหมดอายุที่คำนวณจากวันที่รับหรือวันที่ผลิตบวกอายุการเก็บของรายการสินค้า

   *ข้อชี้แจง (2026-09-26, #7):* **ยอดยกมา** ที่ใช้นำสต๊อกที่มีอยู่แล้วเข้าระบบครั้งเดียวตอนเริ่มใช้งาน ก็สร้าง lot
   ด้วย สต๊อกนั้นรับเข้ามาก่อนมีระบบ จึงบันทึกการรับไม่ได้ และยอดยกมาคือเอกสารต้นทางของมัน ต้นทุนและวันหมดอายุ
   กรอกรายบรรทัดเพราะรู้อยู่แล้ว หลังเริ่มใช้งาน ใบรับสินค้าและผลผลิตจากการผลิตยังเป็นเอกสารเดียวที่สร้าง lot ได้
2. **การผลิตบันทึกผังความสัมพันธ์ lot** lot ผลผลิตทุก lot เชื่อมโยงกับ lot วัตถุดิบนำเข้าที่ใช้ไป พร้อมจำนวน การย้อนรอย
   ไปข้างหน้าและย้อนกลับจะเดินตามการเชื่อมโยงเหล่านี้
3. **lot ที่หมดอายุจะถูกระงับ** lot ที่เลยวันหมดอายุไม่สามารถเบิกจ่าย ใช้ในการผลิต หรือโอนได้ ทำได้เพียงตัดจำหน่ายด้วย
   ใบปรับยอดเท่านั้น
4. **ERP ปันการใช้ที่สาขาแบบ FEFO** event ยอดขายไม่มีข้อมูล lot ERP จะกำหนดการใช้ให้กับ lot ของสาขาตามลำดับ FEFO
   เพื่อการคิดต้นทุนและยอดคงเหลือ
5. **การ recall รายงาน lot ที่เป็นไปได้ ไม่เคยแสดงความแน่นอนที่ไม่เป็นจริง** การย้อนรอยย้อนกลับจากการขายที่สาขาจะให้
   ผลเป็น **ทุก lot ที่อาจถูกใช้อยู่** ที่นั่นในเวลานั้น — คือ lot ที่มีสต๊อกคงเหลืออยู่ที่สาขานั้นในช่วงเวลาดังกล่าว — พร้อมแสดงว่า
   การปันแบบ FEFO ของ ERP กำหนดการใช้ไว้อย่างไร รายงานจะระบุว่าส่วนใดแน่นอน (ผังความสัมพันธ์ lot ในโรงงาน เอกสาร
   การโอน) และส่วนใดเป็นการอนุมาน (การใช้ที่สาขา)

## ผลที่ตามมา

- การย้อนรอยไปข้างหน้าจาก lot ของซัพพลายเออร์ไปถึงสาขาที่รับไปนั้นแม่นยำ เพราะทุกขั้นตอนเป็นเอกสารที่ post แล้ว
- การย้อนรอยย้อนกลับจากจานอาหารแม่นยำจนถึงระดับสาขา และหลังจากนั้นเป็นแบบระบุขอบเขต ไม่ใช่แบบแม่นยำ การอ้าง
  ความแม่นยำเกินกว่าที่ข้อมูลมีจะเป็นวิธีที่เร็วที่สุดในการสูญเสียความเชื่อถือจากใครก็ตามที่เคยทำ recall มาแล้ว
- การย้อนรอยระดับสาขาที่แม่นยำทำได้ในภายหลังโดยการสแกนหรือเลือก lot ตอนเปิดแพ็ก ซึ่งเป็นทางเลือกที่เพิ่มได้ ไม่ใช่สิ่งที่
  v1 แสร้งทำเป็นว่ามี

## ทางเลือกที่พิจารณา

- **รายงานการปันแบบ FEFO ราวกับว่าเป็นข้อมูลที่แน่นอน** ปฏิเสธ: เป็นความแม่นยำจอมปลอม
- **บังคับให้พนักงานสแกน lot ทุกครั้งที่เปิดแพ็กใน v1** ปฏิเสธสำหรับรุ่นแรก: เพิ่มงานในจุดที่วุ่นที่สุดของร้าน และเปลี่ยน
  POS ในแบบที่ผู้ใช้โหมดใช้งานเดี่ยวไม่ต้องการ
