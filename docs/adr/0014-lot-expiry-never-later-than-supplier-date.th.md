# ADR-0014: วันหมดอายุของ lot ต้องไม่เกินวันที่ซัพพลายเออร์ระบุ

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-09-25
- **English:** [0014-lot-expiry-never-later-than-supplier-date.md](0014-lot-expiry-never-later-than-supplier-date.md)

## บริบท

ADR-0006 คำนวณวันหมดอายุของ lot จากวันที่รับหรือวันที่ผลิต บวกอายุการเก็บของรายการ ส่วน ADR-0007 บันทึกวันหมดอายุ
ของซัพพลายเออร์ทุกครั้งที่ตรวจรับ สองค่านี้อาจไม่ตรงกัน: ซัพพลายเออร์อาจส่งของที่แพ็กมาหลายวันแล้ว วันที่พิมพ์บนแพ็ก
จึงเร็วกว่าวันที่รับบวกอายุการเก็บ ถ้า ERP ใช้วันที่คำนวณ ของจะยังเคลื่อนไหวได้หลังวันที่ซัพพลายเออร์รับประกัน และการบล็อก
ของหมดอายุใน ADR-0006 จะไม่ได้ปกป้องอะไรเลยในกรณีที่มันมีไว้เพื่อสิ่งนี้พอดี

## การตัดสินใจ

1. **ตอนรับสินค้า วันหมดอายุของ lot คือวันที่เร็วกว่า** ระหว่างวันที่รับบวกอายุการเก็บของรายการ **กับ** วันหมดอายุของ
   ซัพพลายเออร์ที่บันทึกในบรรทัดนั้น lot เก็บทั้งสองวันไว้ให้เห็นเหตุผล
2. **วันที่ของซัพพลายเออร์ที่เร็วกว่าวันที่คำนวณ ถือเป็นผลการตรวจรับ** บรรทัดนั้นอยู่นอกเกณฑ์และทำตาม ADR-0007: ต้องมี
   เหตุผลและได้รับอนุมัติจากคนที่ไม่ใช่ผู้รับของ ของใกล้หมดอายุรับได้ แต่ไม่ใช่รับแบบเงียบๆ
3. **lot ผลผลิตจากการผลิต** ใช้กฎของ ADR-0006 เหมือนเดิม: วันที่ผลิตบวกอายุการเก็บของรายการผลผลิต **แต่ต้องไม่เกินวัน
   หมดอายุที่เร็วที่สุดของ lot วัตถุดิบที่ใช้ไป** การหั่นไก่ไม่ได้ทำให้ไก่อายุยืนขึ้น
4. การโอนไม่เปลี่ยนวันหมดอายุของ lot (การโอนย้าย lot เดิม)

## ผลที่ตามมา

- การบล็อกของหมดอายุใน ADR-0006 ใช้กับวันที่ที่เชนต้องรับผิดชอบจริง
- หน้าจอรับสินค้าต้องแสดงทั้งสองวัน และบอกว่า lot ใช้วันไหน
- ลำดับ FEFO (ADR-0004) ใช้วันหมดอายุที่ได้ ของที่ส่งมาใกล้หมดอายุจึงถูกใช้ก่อน
- ADR-0006 ถูกขยายความ ไม่ได้ถูกแทนที่: กฎเดิมยังเป็นเพดานสูงสุด

## ทางเลือกที่พิจารณาแล้ว

- **ใช้วันที่คำนวณเสมอ** ปฏิเสธ: อาจเลยวันที่ซัพพลายเออร์รับประกัน
- **ใช้วันที่ของซัพพลายเออร์เสมอ** ปฏิเสธ: ซัพพลายเออร์ไม่ได้พิมพ์วันที่ทุกครั้ง และของที่โรงงานผลิตเองไม่มีวันที่ของ
  ซัพพลายเออร์เลย
- **ปฏิเสธของใกล้หมดอายุทั้งหมด** ปฏิเสธ: บางครั้งโรงงานตั้งใจรับ (เพื่อใช้ทันที) ขั้นอนุมัติทำให้การตัดสินใจนั้นมองเห็นได้
  แทนที่จะทำไม่ได้เลย
