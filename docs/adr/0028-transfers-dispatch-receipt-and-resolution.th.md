# ADR-0028: การโอนสินค้า: ส่งของและรับโอนเป็นเอกสารสองใบ ใบรับโอน post ได้ใบเดียว และทุกจำนวนที่ส่งออกไปต้องถูกรับเข้า ส่งคืน หรือตัดจำหน่าย

- **สถานะ:** เสนอ
- **วันที่:** 2026-10-10
- **English:** [0028-transfers-dispatch-receipt-and-resolution.md](0028-transfers-dispatch-receipt-and-resolution.md)

## บริบท

ADR-0007 กำหนดว่าการโอนต้องผ่าน location ระหว่างขนส่ง การรับโอนที่ปลายทางใช้การตรวจรับแบบเดียวกับใบรับสินค้า และส่วนต่างระหว่าง
ของที่ออกไปกับของที่มาถึง ต้องส่งคืนต้นทางหรือตัดจำหน่าย ห้ามค้างอยู่ระหว่างขนส่ง ADR-0003 กำหนดว่าเอกสาร post รายการทั้งหมดของมัน
พร้อมกัน และเอกสารที่ post แล้วไม่เปลี่ยนอีก แต่พอสร้างการโอน (#14) ยังมีคำถามที่การตัดสินใจเหล่านั้นไม่ได้ตอบ:

- การโอนเคลื่อนสต๊อกสองครั้ง ตอนส่งของและตอนรับโอน ต่างวัน ต่างคน แบบนี้เป็นเอกสารใบเดียวหรือสองใบ
- คนสองคนที่สาขาอาจเริ่มรับของเที่ยวเดียวกันพร้อมกัน ใบไหนนับ
- การตรวจรับเทียบกับอะไร และการโอนจะ "อายุสั้น" ได้ไหม
- ต้องรวมอะไรให้พอดี จึงจะไม่มีของค้างระหว่างขนส่ง
- ใครอนุมัติอะไร ADR-0007 บอกว่าส่วนต่างต้องได้รับอนุมัติ ส่วนอภิธานศัพท์บอกว่าการตัดจำหน่ายมีผู้อนุมัติเสมอ
- จะรู้ได้อย่างไรว่า "ของของใบโอนนี้ยังอยู่ระหว่างขนส่งเท่าไร" ในเมื่อ location ระหว่างขนส่งรวมของทุกใบโอนจากต้นทางเดียวกัน ปนกันตาม lot

## การตัดสินใจ

1. **เอกสารสต๊อกสองใบ** ใบโอนเป็นเอกสารสต๊อก (`transfer`, TR-2026-00001) ที่การ post ของมันคือการส่งของ: ร่าง → ส่งของแล้ว
   หรือยกเลิกก่อนออกเดินทาง ใบรับโอนเป็นเอกสารสต๊อกอีกใบ (`transfer_receipt`, RT-2026-00001) ออกที่ปลายทางโดยอ้างใบโอน:
   ร่าง → ส่งอนุมัติ → อนุมัติ → post หรือถูกปฏิเสธ แต่ละใบ post ครั้งเดียวใน transaction เดียว เหมือนเอกสารอื่นทุกใบ
2. **การส่งของยืนยันสิ่งที่ออกไปจริง** ร่างระบุรายการและจำนวน การส่งของบันทึก lot ที่ออกไปจริง lot ละหนึ่งบรรทัด lot นับเลขต่อกัน
   ทั้งใบ FEFO (#13) แนะนำ lot ตามวันที่ทางธุรกิจของใบโอน คนส่งเปลี่ยนได้ แต่ห้ามใช้ lot ที่หมดอายุแล้วในวันนั้น (`expired_lot`)
   ทุกบรรทัดต้องมีอย่างน้อยหนึ่ง lot (`nothing_picked`) บรรทัดที่ต้นทางไม่มีของให้ลบออกจากร่าง lot น้ำหนักแปรผันต้องออกไปพร้อม
   จำนวนตัว (`pieces_required`) ระบบบัญชีสต๊อกย้าย lot จากต้นทางไปยัง location ระหว่างขนส่งของต้นทาง และปฏิเสธทุกอย่างที่จะทำให้
   ต้นทางติดลบ ต้นทุนและวันหมดอายุของ lot ไม่เปลี่ยนระหว่างทาง (ADR-0004, ADR-0014)
3. **ใบรับโอน post ได้ใบเดียว** ร่างใบรับโอนของใบโอนเดียวกันได้หลายใบ แต่การ post ใบหนึ่งจะ lock ใบโอน ทำเครื่องหมายว่ารับแล้ว
   และปฏิเสธใบอื่นด้วย `already_received` (409) ใบโอนบันทึกว่าใบรับโอนใบไหนเป็นใบที่นำของออกจากระหว่างขนส่ง และฐานข้อมูล
   ไม่ยอมให้บันทึกใบที่สอง ใบรับโอนที่ถูกปฏิเสธจบแค่นั้น สาขาออกใบใหม่
4. **ใบรับโอนตรวจรับทีละบรรทัด lot ด้วยการตรวจรับของใบรับสินค้า โดยไม่แก้** จำนวนที่คาดว่าจะมาคือจำนวนที่ส่งออกของบรรทัด lot นั้น
   ของที่มาถึงคือจำนวนที่นับได้ วันหมดอายุที่คำนวณได้คือวันหมดอายุของ lot เอง และไม่มีวันที่ของซัพพลายเออร์ การโอนจึงไม่เคย
   "อายุสั้น" จำนวนเกินหรือขาด อุ่นเกิน และเสียหาย เป็นผลตรวจนอกเกณฑ์แบบเดียวกับใบรับสินค้าทุกประการ
5. **ทุกจำนวนที่ส่งออกไปต้องมีที่ไป** ต่อหนึ่งบรรทัด lot ผู้รับบันทึกของที่มาถึง และแบ่งจำนวนที่ส่งออกไปเป็น **รับเข้า** (เข้าปลายทาง)
   **ส่งคืน** (กลับต้นทาง) และ **ตัดจำหน่าย** (ออกจากสต๊อก) รับเข้า + ส่งคืน + ตัดจำหน่าย = ที่ส่งออก พอดี รวมจำนวนตัวด้วย
   ไม่อย่างนั้นใบรับโอนถูกปฏิเสธ (`difference_unresolved`) รับเข้าได้เฉพาะของที่มาถึง และส่งคืนได้เฉพาะของที่มาถึงแต่ไม่รับ
   ของที่ไม่มาถึงเลยต้องตัดจำหน่าย ตัดจำหน่ายน้ำหนักโดยไม่มีจำนวนตัวได้ (ไก่น้ำหนักหายระหว่างทาง แต่ตัวไม่หาย) lot ที่หมดอายุ
   ภายในวันที่ของใบรับโอน รับเข้าปลายทางไม่ได้เด็ดขาด (`expired_on_arrival`) ต้องส่งคืนหรือตัดจำหน่าย
6. **เหตุผลและการอนุมัติ** บรรทัดที่มีผลตรวจนอกเกณฑ์ มีการส่งคืน หรือมีการตัดจำหน่าย ต้องมีเหตุผล ใบรับโอนที่มีผลตรวจนอกเกณฑ์
   **หรือมีการตัดจำหน่ายใดๆ** ต้องได้รับอนุมัติจากคนอื่นที่ไม่ใช่ผู้สร้าง และถือสิทธิ์ `transfer:approve_receipt` ซึ่งให้กับบทบาท plant
   คือต้นทางที่ยืนยันว่าของออกไปเท่าไร การส่งคืนอย่างเดียวไม่ต้องอนุมัติ เพราะไม่มีอะไรหาย ใบรับโอนที่ไม่มีทั้งสองอย่าง post ทันที
   ตอนส่ง
7. **การ post ใบรับโอน** ย้ายใน transaction เดียว: ส่วนที่รับเข้าจากระหว่างขนส่งไปปลายทาง ส่วนที่ส่งคืนจากระหว่างขนส่งกลับต้นทาง
   ส่วนที่ตัดจำหน่ายออกจากระหว่างขนส่ง
8. **ของระหว่างขนส่งแยกตามใบโอน คิดจากใบโอนเอง** ยอดของ location ระหว่างขนส่งเก็บราย lot รวมทุกใบโอนของต้นทางเดียวกัน
   เพราะใบรับโอนใบเดียวเคลียร์ของทุกอย่างที่ใบโอนส่งออกไป ส่วนของใบโอนหนึ่งใบจึงเท่ากับบรรทัด lot ที่มันส่งออกพอดี จนกว่า
   ใบรับโอนจะ post `GET /transfers/in-transit?asOf=` ตอบเรื่องนี้ได้ทุกวันที่ทางธุรกิจ และหน้าสต๊อกคงเหลือแสดงคู่กับยอดระหว่างขนส่ง
9. **รุ่นนี้ยังไม่มีการกลับรายการ** ส่งของผิดแก้ด้วยใบรับโอนที่ส่งคืนต้นทางทั้งหมด ใบรับโอนที่ post ผิดแก้ด้วยใบปรับสต๊อก
   การกลับรายการของทั้งสองใบรอ issue ของตัวเอง

## ผลที่ตามมา

- ปลายแต่ละด้านของการโอนเป็นเอกสารที่มีเลข วันที่ คน และ log ของตัวเอง ซึ่งเป็นสิ่งที่คนสืบสวนใช้ไล่ตาม (ADR-0011)
- สาขารับสต๊อกซ้ำสองครั้งจากการส่งเที่ยวเดียวไม่ได้ ไม่ว่าอะไรจะเกิดพร้อมกัน
- ผู้รับบันทึกสามตัวเลขต่อบรรทัด lot แทนตัวเดียว console กรอกกรณีปกติให้ (รับเข้าทั้งหมด) และถามเฉพาะส่วนต่าง
- ERP ยังไม่ได้ผูกผู้ใช้กับ location: ใครถือ `transfer:receive` รับโอนได้ทุกปลายทาง และใครถือ `transfer:dispatch` ส่งของได้จาก
  ทุกต้นทาง การจำกัดเรื่องนี้เป็นอีก issue หนึ่ง

## ทางเลือกที่พิจารณาแล้ว

- **เอกสารใบเดียว post สองครั้ง** ขัดกับ ADR-0003 ที่ให้เอกสารหนึ่งใบ post ครั้งเดียว และการกลับรายการ "ใบโอน" จะต้องเลือกว่ากลับครึ่งไหน
- **ย้ายสต๊อกไปปลายทางเลยตอนส่งของ** ADR-0007 ปฏิเสธไว้แล้ว: สาขาจะเห็นของที่ยังไม่ได้รับ
- **ปล่อยส่วนต่างค้างระหว่างขนส่งไว้เคลียร์ทีหลัง** ADR-0007 ปฏิเสธไว้แล้ว: ของที่ "อยู่ที่ไหนสักแห่ง" คือปัญหาที่การโอนมีไว้กัน
- **ต้องอนุมัติทุกส่วนต่าง รวมการส่งคืน** การส่งคืนไม่ทำให้อะไรหาย และต้นทางเห็นของกลับมาเอง การขออนุมัติตรงนั้นเพิ่มขั้นตอน
  โดยไม่เพิ่มการควบคุม
