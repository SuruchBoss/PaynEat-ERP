# ADR-0025: ใบรับสินค้า: ของที่คาดว่าจะมาในแต่ละครั้ง รับต่อบรรทัดใบสั่งซื้อได้มากสุดเท่าไร และเมื่อไรจึงถือว่ารับครบ

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-09
- **English:** [0025-goods-receipts-expected-quantity-and-completion.md](0025-goods-receipts-expected-quantity-and-completion.md)

## บริบท

ADR-0007 กำหนดว่าการรับของทุกครั้งตรวจด้วยแบบเดียวกัน และอะไรที่นอกเกณฑ์ของสินค้าต้องมีเหตุผลและให้คนอื่นอนุมัติ
ADR-0014 กำหนดวันหมดอายุของ lot ที่รับเข้า ส่วน ADR-0004 และ ADR-0024 กำหนดต้นทุน แต่พอสร้างใบรับสินค้า (#11)
ยังมีคำถามที่การตัดสินใจเหล่านั้นไม่ได้ตอบ:

- จำนวนที่นับได้ของแต่ละเที่ยวเทียบกับอะไร ใบสั่งซื้อมักส่งเป็นหลายเที่ยว และไก่ส่งตามน้ำหนักซึ่งไม่เคยตรงกับที่สั่งพอดี
- รับต่อบรรทัดใบสั่งซื้อได้มากสุดเท่าไร และจะรักษาเพดานนั้นอย่างไรเมื่อใบรับสองใบ post พร้อมกัน
- เมื่อไรบรรทัดหนึ่งและใบสั่งซื้อทั้งใบจึงถือว่ารับครบ บรรทัด 240 กก. ที่ส่งมา 238.4 กก. จะไม่มีวันถึง 240 กก.
- ผู้อนุมัติตัดสินจากผลตรวจตามที่ผู้รับส่งมา หรือจากผลที่คำนวณใหม่ภายหลัง
- ผู้รับนับเป็นหน่วยอะไร
- เกณฑ์ตอนรับของของสินค้าเป็นข้อมูลหลักที่ POS ทุกเครื่องต้องดึงไปด้วยหรือไม่

## การตัดสินใจ

1. **ผู้รับนับเป็นหน่วยซื้อของบรรทัดใบสั่งซื้อ หรือหน่วยหลักของสินค้า** ไก่ทั้งตัวที่สั่งเป็นลังจะชั่งเป็นกิโลกรัมและนับจำนวนตัว
   (ADR-0005) เก็บทั้งจำนวนตามที่กรอกและจำนวนในหน่วยหลัก แปลงครั้งเดียวตอนบันทึกบรรทัด ด้วยการแปลงหน่วยแบบเดียวของ ADR-0019
2. **ของแต่ละเที่ยวคาดว่าจะมาเท่ากับที่ยังค้างในบรรทัดใบสั่งซื้อ** คือที่สั่งลบด้วยที่ใบรับที่ post แล้วรับเข้าไปแล้ว การตรวจเทียบจำนวนที่นับได้กับตัวเลขนี้
   บรรทัดที่ส่งสองเที่ยวจึงตรวจเทียบกับส่วนที่เหลือ ไม่ใช่ทั้งหมด
3. **ใบรับที่ไม่มีผลตรวจนอกเกณฑ์จะ post ทันทีเมื่อส่ง ใบที่มีผลนอกเกณฑ์ต้องรอผู้อนุมัติการจัดซื้อที่ไม่ใช่ผู้สร้างใบ**
   (ADR-0007, ADR-0008) ทุกบรรทัดที่นอกเกณฑ์และทุกบรรทัดที่มีของไม่รับต้องมีเหตุผล การไม่รับของไม่นับเป็นผลนอกเกณฑ์ในตัวเอง
   ต้องมีเหตุผลแต่ไม่ต้องอนุมัติ
4. **ผลตรวจถูกตรึงไว้ตอนส่งใบรับ** สิ่งที่แต่ละบรรทัดคาดว่าจะได้และผลที่พบจะบันทึกไว้ในบรรทัด ผู้อนุมัติตัดสินจากสิ่งนั้นตรงๆ
   ใบที่ตอนส่งอยู่ในเกณฑ์จะถูกตรวจอีกครั้งในธุรกรรม post ถ้าระหว่างนั้นมีใบรับอื่นทำให้จำนวนที่คาดเปลี่ยนจนเกิดผลนอกเกณฑ์
   ใบนี้จะถูกปฏิเสธ (`needs_approval`) และต้องส่งใหม่
5. **บรรทัดใบสั่งซื้อรับเข้าได้มากสุดเท่ากับที่สั่งบวกเกณฑ์คลาดเคลื่อนของสินค้า** หรือเท่าที่สั่งพอดีถ้าสินค้าไม่มีเกณฑ์
   ตรวจในธุรกรรม post หลังล็อกใบสั่งซื้อแล้ว ใบรับสองใบที่ post พร้อมกันจะต่อคิวที่ล็อกนี้ และใบที่สองเห็นสิ่งที่ใบแรกรับไป
   จำนวนที่นับได้เกินเพดานได้ แต่จำนวนที่รับเข้าเกินไม่ได้
6. **บรรทัดใบสั่งซื้อถือว่ารับครบเมื่อรับเข้าถึงที่สั่งลบเกณฑ์คลาดเคลื่อนของสินค้า** หรือถึงที่สั่งถ้าไม่มีเกณฑ์
   ใบสั่งซื้อเป็นรับของครบเมื่อทุกบรรทัดครบ เป็นรับของบางส่วนทันทีที่มีของรับเข้า และคงสถานะเดิมถ้าใบรับไม่ได้รับอะไรเข้าเลย
   เพื่อให้ยังยกเลิกได้
7. **การ post สร้าง lot หนึ่ง lot ต่อบรรทัดที่รับเข้า** ด้วยต้นทุนต่อหน่วยฐานของบรรทัดใบสั่งซื้อ (ADR-0004, ADR-0024)
   และวันหมดอายุตาม ADR-0014 lot เก็บวันที่ทั้งสองไว้ ของที่ซัพพลายเออร์ระบุว่าหมดอายุแล้วรับเข้าไม่ได้ ต้องไม่รับทั้งหมด
8. **ของที่ไม่รับรวมเป็นใบส่งคืนซัพพลายเออร์หนึ่งใบต่อใบรับ** เลขที่ `RTS-YYYY-NNNNN` สร้างโดยการ post พร้อมเหตุผลของแต่ละบรรทัด
   ไม่เปลี่ยนอีก และไม่มีรายการเคลื่อนไหวสต๊อก บรรทัดใบสั่งซื้อบันทึกจำนวนที่ส่งคืนไว้คู่กับจำนวนที่รับแล้ว
9. **สินค้าที่มีเกณฑ์อุณหภูมิต้องวัดอุณหภูมิที่หน้าท่า** ของที่ไม่ได้วัดพิสูจน์ไม่ได้ว่าเย็นพอ จึงปฏิเสธ ไม่ใช่เดาเอาว่าผ่าน
10. **เกณฑ์ตอนรับของเป็นค่าตั้งค่าที่ `admin` ดูแล ไม่ใช่ข้อมูลหลัก** ตั้งผ่าน endpoint ของตัวเอง บันทึกในประวัติการแก้ไข
    และไม่ขึ้นเวอร์ชันข้อมูลหลัก POS ไม่ได้รับค่านี้ และสัญญากับ POS ไม่เปลี่ยน

## ผลที่ตามมา

- การส่งบางส่วนจะเป็นผลนอกเกณฑ์เมื่อขาดจากที่ค้างเกินเกณฑ์คลาดเคลื่อน โรงงานเห็นตั้งแต่ตอนพิมพ์ และผู้อนุมัติตัดสินใจรับของที่ขาดอย่างตั้งใจ
  แทนที่จะผ่านไปเงียบๆ
- ไก่ที่ส่งตามน้ำหนักทำให้บรรทัดครบได้เมื่ออยู่ในเกณฑ์ ไม่มีใครต้องรอไก่ 1.6 กก. สุดท้าย
- สิ่งที่ผู้อนุมัติอนุมัติคือสิ่งที่ถูก post ยกเว้นข้อจำกัดที่การอนุมัติปลดไม่ได้ คือเพดานรับของบรรทัดใบสั่งซื้อและ lot ที่หมดอายุแล้ว
- รุ่นนี้ยังกลับรายการใบรับที่ post แล้วไม่ได้ การแก้ต้องมีเอกสารกลับรายการที่ถอนสิ่งที่บันทึกไว้ในใบสั่งซื้อด้วย ซึ่งยกไปทำใน issue ถัดไป
  ระหว่างนี้ฐานข้อมูลไม่ยอมให้จำนวนที่รับแล้วของบรรทัดใบสั่งซื้อลดลง
- การรับของจากการโอนจะใช้ฟังก์ชันตรวจตัวเดียวกันโดยไม่แก้ (`core/receiving/domain`) โดยใช้จำนวนที่ส่งออกมาเป็นจำนวนที่คาดว่าจะได้

## ทางเลือกที่พิจารณาแล้ว

- **เทียบทุกเที่ยวกับจำนวนที่สั่งทั้งหมด** ไม่เลือก: เที่ยวที่สองของการส่งแยกจะดูเหมือนส่งเกินเสมอ
- **ให้ใบรับ post ได้ไม่จำกัดแล้วค่อยแจ้งเตือนว่ารับเกินทีหลัง** ไม่เลือก: ทั้งสต๊อกและใบสั่งซื้อจะผิดจนกว่าจะมีคนเห็น และ ADR-0007
  กำหนดให้ส่วนต่างต้องถูกตัดสิน ไม่ใช่ถูกกลืนหายไป
- **คำนวณผลตรวจใหม่ตอนผู้อนุมัติกดอนุมัติ** ไม่เลือก: ผู้อนุมัติจะอนุมัติสิ่งที่ต่างจากที่ตัวเองอ่าน
- **เก็บเกณฑ์ไว้ในข้อมูลหลักของสินค้า** ไม่เลือก: POS ทุกเครื่องจะได้เวอร์ชันข้อมูลหลักใหม่และสัญญาเปลี่ยน เพื่อค่าที่ใช้แค่หน้าท่ารับของ
